## 一个有限结果，不是通用工具循环

Writer 可选的连贯续写工作区，为当前**已经保存**的章节提出短草稿：

1. 作者填写方向，明确选择当前目标章作为披露截止，预览准确已保存结尾、服务商／模型与限制。预览不发模型请求，也不自动保存编辑器。
2. 本次独立授权允许一次受限计划请求和一次本地只读工具执行。
3. 模型只可返回 `writer_retrieve_disclosed_context` 的严格 JSON 单计划，参数只有 query；也可返回 `needs_author_input`。宿主验证准确结构、预留一次执行并调用真实已提交来源检索适配。
4. 所有候选初始未选。只有作者逐项选择并明确批准，才能授权第二次请求。
5. 一次受限草稿请求只收到方向、同一预览结尾与已选私有原文附件，不带计划对话或未选候选。
6. 完整且仍有效的草稿展示给作者。复制／丢弃不写正文；独立的**追加并保存**按钮在重新校验后，最多插入一次已转义文本。

这是真实执行边界：宿主拥有 run／call 身份、授权能力、输入验证、预算预留、私有准备对象和已验证回执。模型一句话或外观正确的 UI 对象不能伪造工具结果／已选原文租约。模型可决定查询，却不能观察检索后再次规划。这是在受限非流式 API 上执行的单工具类型协议，**不是供应商原生函数调用**或 SDK 递归工具循环。

不引入 Pi、第二套模型配置、refine 请求、自动修复／重试、远程 MCP、网页／URL 工具、脚本、无人值守任务、整章替换、图谱修改或隐藏文档历史。旧 Assistant 工具开关不给此工具授权。阶段二存储／编辑器重构仍独立。

## 原文与明确披露

续写目标必须等于作者明确选择的截止章。选择更早截止时，在读取用于发送的目标结尾和第一次模型派发前阻止，不自动推后截止。切章、章节顺序／来源／截止／配置改变均撤销旧授权。作者手填方向是另行展示的输入；应用不能保证手填内容本身没有剧透。

工具封装 `prepareWriterMemoryContext`，锁定项目／目标／截止、准确 expected target，明确 `includeGraph:false`、无远程服务、limit 六、附件 6,000 单位。只运行一次真实本地 Worker 同步／检索准备，不重复旧词面扫描。每条来源仍验证当前修订、精确 UTF-16 位置／原文与披露成员关系。首版不含图谱，避免宣称小说与图谱的跨存储原子事务。

只有已保存、已提交正文权威。标题／大纲／素材／其他小说、未来章节、模型自由参数和释义不能扩大来源。已经归一化的正文不再次清洗；字面实体和代理对有固定测试。检索分数不等于语义可信度或支持结论。

初次准备对象及完整预览**不代表已批准上下文**。runtime 私有保留原始候选和选择函数，UI 副本／复制回执不形成能力。作者逐项批准前，不发送检索原文。无候选、拒答、坏计划或请求失败都明确停止，不兜底无依据写作、不二次检索、不暗中再规划。

## 固定限制

| 资源 | 首版上限 |
|---|---|
| 模型请求 | 最多两次：计划与草稿；每次一个 HTTP attempt，不自动重试 |
| 输出额度 | 每次 1,200 tokens，合计 2,400 配置输出额度 |
| 本地工具 | 一次 `writer_retrieve_disclosed_context` 执行 |
| 方向／query | 1–1,000／1–200 UTF-16 单位 |
| 已保存目标结尾 | 最多 2,000 单位，准确片段位置／修订，不切断代理对 |
| 已披露来源规模 | 最多 2,500 章、12,000,000 归一化单位；超限拒绝，不抽样 |
| 候选／已选附件 | 最多六条／6,000 单位，完整来源单位打包 |
| 计划／可接受草稿 | 最多 1,200／2,000 单位；空、未完成、超长不能裁成成功 |
| 序列化应用输入 | 最多 16,384 UTF-16 单位及 65,536 UTF-8 字节，含 JSON 转义／包装 |
| HTTP 响应 | 最多 65,536 解码字节，含错误／推理 envelope；拒绝重定向 |
| 模型／来源 guard／检索 | 30 秒／10 秒／90 秒 |
| 提交前 active 工作 | 累计 180 秒，作者审阅不归零 |
| 未应用运行过期 | 绝对 20 分钟，含作者等待 |
| 审计 | 最多 32 个有界结构事件；超限停止，不偷偷丢弃动作 |

配置输出额度**不是费用上限**，也不是所有隐藏推理费用的通用保证。仍执行现有供应商受限 thinking 检查。真实 reported usage 按请求精确归属，与配置额度分列；缺失即未知，不是零。后续草稿失败不能抹去已完成计划的用量观察，不借全局“最新账单”猜本次消耗。

来源规模检查发生在现有适配读取已提交数据之后，不是全库 hydrate／其他小说的分配上限。截止能及时撤销权限，但不能抢占同步 JSON 解析或已经发出的存储读。它限制之后获准的工作，不是整个应用 CPU／RAM 硬界。已经开始的持久保存是单独不可取消边界，不强迫在模型／运行时限内结束。

## 所有权、取消与原文新鲜度

runtime 锁定项目／目标／截止、准确编辑器 HTML、方向、配置身份、来源指纹、run epoch 和私有证据租约。密钥／headers 仅内存比对，不入审计。每次 await 后、真实 HTTP 派发、响应后、结果就绪前和首次应用前重新检查。只改格式也会使未应用草稿失效。

私有读取端口和 MemoryClient 门面在 read／sync／search 前后同步核对所有权。单靠 abort 加 dispose 不够，因为普通 MemoryClient 之后可重新创建 Worker。guard 刚 resolve、随后取消时，其 continuation 不能再开始 sync／search。迟到响应、旧 finally 和旧批准不能影响新运行。

取消、窗口 X／Escape／遮罩、输入／配置改变、路由／切章、其他生成抢占共用同步撤销。重开不恢复原文、授权或草稿，也不自动请求。卸载只是展示行为，不是权限。取消不能召回已发数据或证明费用为零。

## 追加、普通保存回执与恢复

Apply 先取得 Writer 门闩，再验证私有已选租约。首次修改前仍可取消。最后一次 await 后，同步核对 owner／原始 HTML，消费一次性草稿能力、锁定原应用身份并恰好追加一次转义文本。末次核对与首次修改之间没有 await。

真实编辑器须在草稿能力尚未消费时，先准备一次性的同步应用端口。准备时实例缺失或已销毁，须在修改前失败并释放临时租约。锁定应用身份后，端口同步执行已安装编辑器的 `setHtml` 再 `getHtml`，以**编辑器规范化后的 HTML 作为首次保存快照**；随后等值 model／change 通知不应再存一次，真正作者新编辑仍正常补存。这不是只删除换行，也不改变普通持久化。首版在私有草稿或真实既有编辑器文本含可解码的 HTML 实体字面序列（例如原样的 `&lt;`、`&#60;`、`&amp;` 字符）时，拒绝自动追加，因为当前已安装 serializer 会在重新载入时改字。这项只读检查发生在消费与修改前，给出具体原因并保留草稿复制。宿主固定 validator 是纯同步函数，runtime 随后再次检查所有权；零消费拒绝保证针对该固定 validator，不泛称任意带副作用回调都不会消费。不笼统禁止普通 & 或实际尖括号文字，不静默改写文本，也不重构整个编辑器。如果端口在可能已经开始修改后抛错，草稿能力保持已消费、原草稿仍可复制，状态保守为 unknown，不恢复再次 Append 权限。

保存沿用现有普通 capture／merge／stage／CAS 路径，不做全库替换。在真实元数据提交点生成请求级**纯元数据回执**。这个新增回执回调的异常不能撤销已提交事实或再发请求。既有全局状态观察者的异常传播保持不变，包括受跟踪的备份恢复回滚。同项目其他标签页修改被拒绝，不静默 rebase；不同小说的并发提交仍可合并。

仅 Agent 应用租约使用单个 Writer save handle 与快照 drain。普通非 Agent 保存保留既有逐快照完成结果，避免后续保存失败把先前已提交结构改动误回滚。header 重试、全局重试、自动保存与 dispose 的并发调用不能产生重复 pending 保存。只有真实作者新编辑才产生 catch-up 快照。普通正文编辑仍保留；结构性改动须在乐观修改前守卫，延迟删除确认／文件读取之后也重新检查。既有生成／mutation 屏障防止跨过已开始的提交。

UI 区分：

- **Clean：**保存 drain 完成，没有残留未保存修改。
- **已知失败：**保留已经追加的正文，只能凭同一恢复 token 明确重试保存，不再 Append／模型调用／检索。冲突不授权刷新 CAS 基线或覆盖。
- **Pending／unknown：**保留原操作与屏障，可复制，不可重试／再次追加。30 秒仍无已知提交或完成结果时，本地指示仅将同一 handle 标为 unknown，不结束、取消、释放或重试写入。实际提交回执会取消等待计时器；若此前已显示 unknown，整次操作可继续等待完成，但必须显示最初追加已提交，不能把该事实重置为零或未提交。等待超时不是回滚证据，迟到完成仍归原 handle。
- **最初追加已提交、随后 catch-up 失败：**保留最初提交事实，说明作者后续编辑未存，不能声称整次追加未提交。

Agent 保存请求仅在进程内标记为明确恢复，不把标记写入小说；共享缓存仅在成功后发布，失败 Agent 快照不能混入之后的普通项目保存。同一 backend 尚有 pending Agent 请求时，新普通保存须在改动缓存、revision 或请求状态之前拒绝。普通非 Agent 缓存／CAS 行为不变。

generic header／全局重试不得暗中重试 Agent 恢复，由面板承担明确恢复动作。自动保存／dispose／导航不隐式重试失败 Agent 保存。首次追加后关闭／导航等待真实结果；未修改前安全取消可释放临时屏障。持久保护来自已有同项目 CAS，不是异步 freshness 单独提供。

章节 CRUD 在登记自身屏障前等待其他 owner；已提交后的内部选章不重新等待同一 CRUD 屏障。撤销其他范围前先做无副作用意图校验，最后同步认领拒绝过期表单／确认及新进入待提交状态的 owner。
