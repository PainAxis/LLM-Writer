## 行为与边界

本地索引现在从章节正文片段、章节标题以及有效作者伏笔标签／别名中记录精确代码。识别规则是完整的 ASCII 连续串：至少一个字母和一个数字，允许内部单个连字符或下划线，不区分大小写，最多 64 字符，例如 `FS00001`、`AB-12`、`ZX_45`。纯数字、普通纯字母单词、分隔符不合法或超长的串不进入精确代码通道。`FS000010` 中的 `FS00001` 等前后缀片段不算完整命中；分块边缘会对照相邻原文字元检查。

精确代码候选与普通正文／伏笔共用索引生命周期。限定候选数量前先过滤作品和披露范围。本地检索优先排列覆盖更多不同查询代码的候选；代码不存在时，仍保留普通关键词／伏笔检索。结果原因区分代码来自引用原文、章节标题或作者标注；标题／别名匹配不代表代码出现在正文引用中，精确代码也不证明片段回答了问题。

可选嵌入和重排仍须主动开启，并可改变最终顺序。本次修复不需要图谱标注、检索密钥或服务请求。Writer 保持明确的预览核对、来源复验及 6,000 字符依据预算，详见[写作依据规则](writer-memory-context.zh-CN.md)。

新增代码通道不会在查询时额外全文扫描一次稿件；原有来源读取、候选资格遍历和精确原文校验仍会检查已提交快照／依据。这不代表端到端查询复杂度已低于线性，也没有解决冷启动或峰值内存问题。

## PR #35 验证

```bash

```

专项冒烟检查原先掉出候选窗口的来源、代码语法及相似串、多代码覆盖、标题／别名来源标识、分块边界、候选截断前的作品／披露过滤、修改／删除／重排同步、取消恢复以及可选服务排序。普通中文和伏笔检索继续由现有记忆测试覆盖。

压力运行器保留每档原有 **11 组／68 次准备**及混合查询加图谱的记录，在 `originalWorkload` 处记录原工作负载指标，再追加 **24 次使用原始完整混合问题、关闭图谱／嵌入／重排的硬性断言**。因此每档现有 **12 组／92 次准备**。每条接纳来源仍需通过当前章节、修订、精确范围／引用及披露校验。远距离伏笔、旧章和批量改稿、未来身份及作者确认的多前提关系保留原验收。不调用付费或真实服务；每档一次受控重排请求后，检查来源变化能阻止下一次外发。

真实构建的 Writer 浏览器测试用完整问题检索无图谱标注的精确正文，再检查预览、实际生成请求、旧章修改及未来代码截止范围。派生的持久化语料共 600 章／1,423,494 个正文字符；Writer 截止范围披露 598 章／1,423,398 字符，精确代码及身份揭晓分别留在叙事顺序第 599、600 章。序列化小说为 1,539,531 字符，超过持久化拆分阈值，共 593 个拆分章节正文。原有四条图谱锚点全部保留，但都不覆盖受测正文。这些浏览器指标与 Node 工作负载分开计量。PR #35 的配置共 **77 组冒烟／129 个浏览器场景**，其中 Writer 记忆 **16 个场景**。当前覆盖范围见[目录结构](../PROJECT_STRUCTURE.zh-CN.md)，验证状态以审查提交的 CI 为准。

## 第三阶段剩余工作

后续[依据审阅工作](memory-evidence-review.zh-CN.md)增加确定性的匹配／缺失编号提示和 Writer 逐项选择；以上测量保持不变，也不宣称语义可回答性已经成立。

1. **无答案与低相关性处理：**代码不存在或已披露来源无法回答时，仍可能返回部分匹配。来源有效和结果非空不足以证明存在答案，拒答行为需要单独定义及测试。
2. **索引与语义容量：**冷启动、完整已提交来源读取／验证、恢复／整理及有限语义缓存仍有性能或容量限制。Node 测量不含 IndexedDB 加载、Worker 传输、编辑器渲染和真实服务延迟。

全书自动抽取仍需单独设计。本轮不扩大第二阶段持久化／编辑范围，第四阶段 Agent 继续暂缓。
