# 可选的带引用语义支持核对

[English](memory-support-checks.md) | [简体中文](memory-support-checks.zh-CN.md)

第三阶段第 3 项增加一项可选、由作者明确启动的聊天模型核对：针对**一个问题，以及逐项选中的、当前修订且已披露的原文**给出意见。普通本地检索与已完成的可选语义检索都可使用。它不是另一种检索模式、全书无答案检测器，也不是第四阶段 Agent。

## 三种模型意见，不是事实认证

| 模型意见 | 仅在所选原文范围内的含义 |
| --- | --- |
| `supported`（支持） | 模型认为其回答有依据，并为每个所述前提引用原文。原文明示的否定或纠正性回答也可以得到支持。 |
| `insufficient`（不足） | 当前选择缺少必要事实或前提，**不代表全书没有答案**。已有部分依据和缺失信息仍逐项显示。 |
| `uncertain`（不确定） | 矛盾叙述、身份或时间歧义、未经确认的说法或推理跳跃，使模型无法可靠回答；相关前提仍附引用显示。 |

程序验证的是返回协议与当前原文位置，**不能证明语义蕴含或模型推理正确**。引用位置正确但回答错误仍可能发生。不会把相似度、数值门槛转成置信度。原有词面／编号指标及其 `answerability: unverified` 保持不变，新面板是独立的辅助意见。

关闭、未运行、取消、不可用、过期源、超时、格式错误和请求失败都保持**未验证**，不能冒充成功的“不足”或“不确定”。原文没有提到某事，不能据此给出否定事实。问题自带的前提、标题、别名和作者标注都不是证据。完整的简单多前提链可以得到支持；对所有问题一律拒答不能通过验收。

## 作者操作流程

在 Memory Lab 完成检索，明确勾选原文段落，再开启独立的支持检查选项。Writer 沿用逐段原文／整条关系的选择方式。选中一条关系就包含其全部原文前提；任一前提过期或未披露，整组选择都不能使用。

核对问题初始为检索问题，也可以单独修改。修改它会让旧核对失效，但不会偷偷扩大证据范围或自动重新检索。先准备**纯本地预览**，检查问题、完整引用、原文修订、当前聊天模型／目的地与预算，再明确发送。准备阶段不调用服务商。Embedding、rerank 和全范围扫描授权不会连带开启聊天核对；未完成扫描的部分结果不能选作依据。

结果逐项显示模型描述的前提及其精确原文，并显示回答、解释、缺失／未解决信息。返回文本按文本显示，不执行 HTML 或 Markdown。模型载荷只包含问题和原文引用，不包含章节／项目标题、标注、关系谓词、检索分数或完整章节。

在 Writer 启动核对会撤销旧的生成批准；检查期间不能批准。检查完成，即使结果为“支持”，也不会自动选择或批准证据。正文生成、续写和润色都仍需作者明确批准所选引用，并通过原有发送、完成与应用时的新鲜度检查。**核对产生的回答和解释不会加入写作提示词或正文。** 作者阅读“不足／不确定／未验证”提示后，仍可明确批准当前有效的参考原文。

核对、预览和结果只存在于当前路由会话，不写成图谱事实或进入备份。聊天凭据沿用现有配置，不新增凭据存储。用量记录不保存问题、引用、回答和推理正文，只保留可取得的用量元数据。目的地预览不显示 URL 用户信息、查询参数或请求头值；配置了代理时，同时展示代理来源站点。

## 明确的输入与调用预算

这些数字是输入／成本上限，**不是可信度门槛**。超限会拒绝整个选择，不静默截断引用或丢弃关系前提。

| 项目 | 上限 |
| --- | --- |
| 问题 | 1–500 个 UTF-16 代码单元 |
| 原文选择 | 1–8 个完整唯一锚点；每段最多 2,000，合计最多 8,000 个代码单元 |
| 完整 system + JSON 用户输入 | 最多 16,000 个 UTF-16 代码单元及 48,000 个 UTF-8 字节 |
| 服务商尝试 | 每份预览最多一次 HTTP 生成请求 |
| 请求输出 | 最多 1,200 个总输出 token，包含适用的推理分配 |
| 返回输出 | 模型文本最多 8,000 个代码单元；解码后的 HTTP 响应体最多 65,536 字节，包含错误／推理包装 |
| 处理时间 | 启动后累计 45 秒；服务商等待最多 30 秒；单次来源校验最多 10 秒，均受剩余总时间限制 |
| 本地准备 | UI 整个准备路径累计 10 秒，包括 Writer 进入核对引擎前的已保存原文读取 |
| 待发送预览 | 五分钟后失效，需要重新准备 |

请求级适配器禁用 SDK 重试、工具、修复循环、模型回退及重定向。在 SDK 解析 JSON **之前**限制读取到的响应体，即使 Content-Length 缺失／不实、错误体过大或流停滞也适用。序列化原文中的控制字符及非 BMP 字符按原样保留。没有启用这些可选限制的普通请求保持原有行为。

服务商专用 token 规则继续生效。例如，有界 Qwen 请求必须使用可计算的有限独立推理预算，或明确关闭推理；可见输出与推理之和不得超过所请求的总上限。必须推理的模型仍遵守原有模型策略。不支持的设置会安全失败，不悄悄改成无限预算或换模型。

即使依赖忽略取消信号，取消仍会让当前操作结束；迟到输出不能恢复旧状态。连续点击复用一次性结果，不会多次发送。重新检查是新的明确请求，不是自动重试。错误只显示安全分类，不显示服务商原始诊断或请求头。

## 各个边界都核对当前原文

异步操作前先保存私有输入副本。服务检查项目／截止章节身份、清单一致性、全部引用修订、精确 UTF-16 范围、完整引文与代理对边界；独立重算所选章节哈希，在哈希之后及发送／发布之前重读已保存原文。

路由还绑定检索问题、独立核对问题、选择、Writer 实际目标、图谱及私有服务配置身份。任何一项改变都会让旧预览／结果失效。storage／焦点／可见性刷新只是附加保护，不代替已保存原文读取。保存失败、旧编辑器草稿、未来来源和作者确认都不能绕过校验。

来源或图谱校验失败，包括来源读取挂起超时，会清除旧预览、候选和选择，并要求重新检索。纯服务商失败可以保留确实仍有效的原文候选，但旧批准仍已撤销，后续使用依然要校验并明确批准。最终解析、引用映射与发布不会额外获赠处理时间。

## 冻结验收集及结果口径

[小说固定集](../scripts/fixtures/support-check-fixture-v1.json) 包含 **33 例**：25 个语义用例（12 支持、6 不足、7 不确定）和 8 个操作安全拒绝用例。SHA-256 为 `ebf0a7ea662e6ddd3e2079598954888cd553c72ae74c666691ae822704b20c2d`，在实现对比前已冻结。包含改写问题、明确否定、原文照录但无人回答的问题、缺失／完整多前提链、矛盾说法、歧义、未来才有的答案和注入指令。

受控响应经过生产解析器、私有引用映射和生命周期。语义用例要求 26 个指定前提，解析 27 条引用。全返回“不足”的变异策略错 19/25，其中包含全部 12 个正例；全返回“支持”错 13/25。解析器无法识别所有“引用正确但语义错误”的回答，金标准评估必须把这种结果计为质量失败，而不能声称它不可能发生。

构建产物的浏览器套件另行贯穿全部 25 个语义用例，并覆盖格式／超大／流中断／请求失败、假引用、发送和发布边界的原文变化、迟到成功、选择／配置／问题／披露范围变化、未完成扫描和窄屏。单独的 `support-enabled-long-novel-v1` 配置含 600 章、1,388,902 字符，其中披露到第 599 章的范围为 1,388,828 字符。精确依据位于第 588／590 章，覆盖 Lab 和三种 Writer 生成流程；第 600 章的未来信息哨兵必须排除。此扩展不改变冻结的 25 个语义案例分母。完整套件要求 52 个场景、50 次支持请求、3 次写作请求和 62 次已选来源传输；长篇配置另要求 4 次支持、3 次写作、0 次检索服务请求和 8 次支持来源传输。这些是配置中的断言，不代表尚未执行的浏览器已经通过。Node 测试通过不能代替浏览器结果。
