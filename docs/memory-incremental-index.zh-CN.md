# 记忆增量索引

[English](memory-incremental-index.md) | [简体中文](memory-incremental-index.zh-CN.md)

记忆检索现在可更新受影响章节及伏笔，不必每次重新对整部小说分词。检索实际小说时，从另一标签页的 Writer 返回也会保留已完成的 Worker 基线及兼容正文向量。这扩展了[检索原型](memory-prototype.zh-CN.md)，不改变 Writer 持久化，也未将检索接入生成。

## 同步约定

每次检索仍读取最新已提交来源，并验证完整快照。索引复用取决于来源身份和精确内容，不信任保存时间戳。同步开始先使旧索引不可用，并取消旧异步工作。

| 来源变化 | 索引工作 |
| --- | --- |
| 完整来源未变 | 复用已验证索引及修订号 |
| 章节标题／正文变化，或新增章节 | 对该章计算哈希并切片，替换受影响的关键词索引条目 |
| 删除章节 | 删除其正文片段及伏笔，淘汰不兼容的正文向量 |
| 新增、修改或删除伏笔 | 按当前章节修订号与精确原文范围重新验证，更新受影响的伏笔条目 |
| 章节顺序变化 | 更新披露顺序及依据元数据，不对未变条目重新分词 |
| 切换作品，或没有可复用的已完成基线 | 建立新索引 |

未变章节保留修订号及切片。每个伏笔仍绑定精确的章节修订号和引文：来源章修改后旧标记即失效，即使部分文字未变。伏笔标签及别名不是自动事实抽取，且不能提前泄露后文。

同步期间，已完成基线只由一个构建任务持有。构建失败或被更新请求取代后，部分修改的数据库不能用于检索，也不能充当下次可复用基线；下一次成功构建可从全新索引恢复。检索拒绝旧构建版本，服务请求及依据展示前仍检查来源、修订号、范围和披露上界。

Orama 删除条目后会保留部分元数据。为限制连续改稿时的累积，累计删除数量加上本次计划删除量超过 **1,024 与下次有效条目数两倍中的较大值**时，引擎会重新建立数据库。这次整理可复用未变章节的哈希与切片，但须重新插入全部有效关键词条目；精确来源向量仍可独立复用。因此增量更新不代表保存耗时恒定，也不代表永远无需重建。

## Worker 与向量缓存生命周期

| 事件 | 可见状态与保留数据 |
| --- | --- |
| 实际小说：窗口获得焦点或小说存储失效通知 | 清除结果、依据及就绪状态，取消未完成工作；内部仅保留已完成基线及兼容向量。重新读取已提交来源并同步成功后，才可检索。 |
| 修改查询或截止章节 | 清除旧结果，后续检索使用当前查询及披露范围。 |
| 主动取消、修改服务设置、清除缓存或切换作品 | 销毁 Worker，丢弃索引及向量。 |
| 离开或刷新记忆检索页面 | 销毁 Worker，并清除路由会话中的服务设置及凭据。 |

从 Writer **标签页**返回可复用仍然存活的记忆检索 Worker；离开记忆检索**路由**仍会结束该生命周期。索引及向量缓存不写入持久存储，也不进入备份。

向量键仍包含作品、章节修订号及精确范围，并按服务、模型、维度和账户隔离。修订号取完整标题及正文，因此修改一句话会使该章所有片段向量失效；符合披露范围的未变章节可复用向量，查询每次重新嵌入。**2,000 片段／32 MiB 缓存**、**每批 32 片段**、**单次请求 15 秒**、**远程总预算 65 秒**及 **60 个重排候选**均保持不变。调整顺序或缩小截止范围不会让缓存中的未来正文变得可用。

## 验证

```bash
npm run smoke:memory
npm run smoke:memory-incremental
npm run smoke:memory-client
npm run smoke:memory-hybrid
npm run test:memory-stress-local
npm run test:memory-stress-hybrid
npm run build
npm run test:browser-memory-hybrid
npm run test:browser-memory-stress
```

增量冒烟检查来源变化、陈旧伏笔、删除／重排、失败恢复、并发同步及连续改稿整理。客户端冒烟检查保留 Worker 的来源失效、拒绝未完成请求及重新同步恢复。实际构建产物的浏览器测试检查焦点／存储失效、重新读取已提交来源及迟到的服务响应。

较大工作负载沿用已有百万、数百万及千万字符语料。本地测试增加连续单章版本保存；受控 HTTP 测试要求只重新提交修改章节的正文向量。600 章浏览器工作负载要求来源未变时返回焦点不重新嵌入正文，实际 Writer 保存后仅重新嵌入修改章的片段，并独立核对全部未改章节正文和未来披露边界。主动取消及清除缓存仍须冷启动恢复。

`MemoryIndexStats.sync` 记录 `full`、`incremental` 或 `unchanged`，以及重新构建／复用章节数和插入／删除／复用条目数。章节数量表示哈希及切片工作，条目数量表示关键词索引工作；整理时可以复用章节工作，但仍插入全部条目。整体替换索引不会将丢弃条目计为就地删除。报告应同时记录这些数量与耗时，避免把漏做工作或全量重建误认为快速增量。

报告位于 `artifacts/memory-stress/` 及 `artifacts/browser-memory-stress/`。[PR #30 实测](memory-stress-tests.zh-CN.md)继续作为历史基线，保留当时全量重建及缓存丢失结果。发布新结果时应固定语料，并标明受测版本和环境；浏览器完整操作耗时不能与仅测引擎同步的耗时混比。

如需用同一套运行器对照引擎，准备 PR #30 的独立工作目录，再用当前版本的脚本分别运行两个引擎：

```bash
git worktree add --detach ../LLM-Writer-memory-baseline b77327a
npm --prefix ../LLM-Writer-memory-baseline ci
node --import tsx scripts/benchmark-memory-incremental.ts --engine-root=../LLM-Writer-memory-baseline --label=before
node --import tsx scripts/benchmark-memory-incremental.ts --label=after
```

可选 `--profile=million|three-million|ten-million|all` 选择体量，`--output=...` 更改默认的 `artifacts/memory-incremental/` 输出目录。每组在独立子进程运行，报告保留脚本、语料、引擎及来源哈希、同步工作量、内存观察和精确原文检查。计时仅包含同步调用，不含准备、克隆、主动垃圾回收、检索及写入报告；禁止服务请求。应保持可比较的运行环境，并同时保留失败和成功结果。

## 仍然存在的边界

首次索引、完整来源读取、快照复制和验证仍随稿件大小增长。周期性整理与失败恢复仍有全量构建路径，内存索引也可能占用较大空间。语义容量和真实服务冷启动限制并未提高。本次改动不改善已测出的无答案识别问题，不提供持久后台索引，也未完成章级持久化、事实关系图或生成上下文接入。
