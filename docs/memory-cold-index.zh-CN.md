# 保持词频评分等价的记忆冷索引优化

[English](memory-cold-index.md) | [简体中文](memory-cold-index.zh-CN.md)

本次聚焦的第三阶段改动消除 Orama 插入期间重复的词频计数，不改变分词、排序、依据、披露或资源上限，也不代表第三阶段完成。[四条完成契约](../ROADMAP.zh-CN.md#第三阶段完成契约)界定剩余工作与第四阶段受限入口。

## 为什么选择这个改动

对既有百万字符工作负载的剖析显示，冷构建热点集中在 Orama 插入及逐词词频扫描。一轮探索性的 CPU 剖析约用 9.85 秒完成冷同步、9.70 秒完成新实例重建。这些数值包含 CPU 剖析开销，只用于定位热点，**不是**前后提速对照基线。

Orama 3.1.18 的默认评分钩子在插入每个词时扫描字段的完整词数组。`src/services/memory/tokenScoreIndex.ts` 使用公开的 `components.index.createIndex()` API，仅覆盖文档／词评分钩子：

- 用 `Map` 一次统计字段词频，并以词数组身份为键缓存于 `WeakMap`。
- 每个文档字段开始时先使计数失效，再调用默认文档评分钩子。分词器可能复用并修改同一个数组，数组身份本身不代表内容新鲜。
- 沿用默认内部文档 ID、词频分母及出现次数赋值，包括重复／空词和继承属性行为。
- 保持既有 MemoryIndex 分词器，以及默认基数树、插入／删除／搜索行为与 BM25 公式。不打依赖补丁、不对词去重、不换评分公式，也不增加持久化索引快照。

字段含 n 个词时，确定性冒烟计数器观测该计数／插入路径的词访问数从 **n² + n 降至 2n**。这只断言此路径的复杂度，不代表完整索引或所有查询都是线性的，也不代表必然提速两倍。

## 等价与安全检查

`npm run smoke:memory-token-scores` 将完整 Orama 保存状态及精确搜索评分与默认组件对比。案例包含重复项、空字符串／空数组、原型键、Unicode、多字段、字符串数组、删除、重新插入、更新、保存／加载与复用的可变分词数组。直接调用钩子的边界案例保留默认行为，包括空分母产生的 NaN。访问次数断言不依赖耗时阈值。

增强的容量测量代码记录每个**完整检索结果，仅排除 `searchMs`** 的 SHA-256，包含依据、章节修订、精确原文范围、排序、返回的融合分数、原因、诊断与保守评估。查询覆盖精确编号、中文／代码混合、作者伏笔、自然问题、已知无答案问题、旧事实排除与披露边界。保留原有漏召回，不为改善对照而移除查询；评估均保持 `answerability: unverified`。生产 `MemoryIndex` 结果返回倒数排名融合分数，并非原始 Orama BM25 分数；原始 Orama 评分状态与搜索分数由 `smoke:memory-token-scores` 另行检查。

比较器要求语料、来源哈希、章节指纹、索引工作量、完整结果摘要与来源检查次数相同，仅允许生产 `engine.ts` 组件接线及新增 `tokenScoreIndex.ts` 不同。还要求生产修订干净可识别、测量代码／环境相同、四次完整且不重叠的 ABBA 运行，以及零服务／网络请求。耗时和内存是观测值，不是通过阈值。`smoke:memory-cold-comparison` 拒绝不完整／脏报告、遗漏或改变依赖、测量代码／语料／机器变化、运行重叠、来源／工作量／结果变化、删除查询、隐瞒网络／服务请求和无效耗时。即使候选所有阶段都更慢，只要报告等价仍可通过，避免性能阈值筛掉退步样本。

这些 Node 检查不能替代生命周期或界面验收。当前生产的冒烟、压力与构建后业务套件继续保留取消、过期／迟到响应拒绝、保存失败、并发变更、每条图谱前提、披露／未来隔离及 Writer 明确选择依据。Memory Lab → Writer 正文生成、续写与润色仍须分别业务验收。是否通过由受审修订的完整 CI 确定，而不是文档中配置的测试数量。

## 受控测量

基线为已合并正文加载优化的 `7739cb0f6d020e4e05d0bff8d9d18f59f3d903c0`；受测候选生产修订为 `b8a3c4b895ab0f8cab167194701f7a42c2bdca8b`。每档使用同一机器上的新进程，按**基线、候选、候选、基线（ABBA）**运行，每种实现两个观测。两端均使用相同的当前测量代码；2026-10-08 的历史 Node 或 Chromium 数值不是此次对照基线。

2026-10-22 本地运行使用 Node v24.19.0、Linux x64、AMD EPYC 9V74，暴露九个逻辑 CPU，约 9,967 MiB 总内存，V8 堆上限 2,240 MiB，并启用显式 GC。工作负载为冻结的版本 2 程序化中文小说：600 章／1,320,000 个 UTF-16 字符及 2,500 章／10,500,000 个字符。它们不是阅读字数统计，也不是较早的 144 万字符 Writer 语料。

### 解释边界

每种实现两次运行仅提供描述性中位数、范围和原始观测，不是延迟分位数、统计置信结论、通用设备保证或 SLA。记录必须保留耗时上升与下降、用户态／系统态 CPU、堆／RSS 及语料／实现／测量代码哈希。显式 GC、语料准备与依据检查在受测同步调用外；进程内存包含完整工作负载，端点采样可能遗漏同步峰值。

这是 Node 引擎测量，不包含 IndexedDB 来源加载、Worker 传输、浏览器渲染、编辑器行为、真实服务延迟或模型／写作质量。新实例恢复仍为全量重建，优化没有靠减少稿件覆盖获得更快结果。

## 复现

在依赖已安装且干净的候选检出目录内，将独立基线 `7739cb0f6d020e4e05d0bff8d9d18f59f3d903c0` 检出到 `.cold-index-baseline`。全程使用候选的同一测量代码，顺序执行，避免并发高负载任务：

```bash
npm run smoke:memory-token-scores
npm run smoke:memory-cold-comparison
for profile in million ten-million; do
  node --expose-gc --import tsx scripts/benchmark-memory-capacity.ts --engine-root=.cold-index-baseline --profile=$profile --label=baseline-a --output=artifacts/memory-cold-index
  node --expose-gc --import tsx scripts/benchmark-memory-capacity.ts --profile=$profile --label=candidate-a --output=artifacts/memory-cold-index
  node --expose-gc --import tsx scripts/benchmark-memory-capacity.ts --profile=$profile --label=candidate-b --output=artifacts/memory-cold-index
  node --expose-gc --import tsx scripts/benchmark-memory-capacity.ts --engine-root=.cold-index-baseline --profile=$profile --label=baseline-b --output=artifacts/memory-cold-index
  node scripts/compare-memory-cold-index.mjs \
    --baseline=artifacts/memory-cold-index/baseline-a-$profile.json \
    --baseline=artifacts/memory-cold-index/baseline-b-$profile.json \
    --candidate=artifacts/memory-cold-index/candidate-a-$profile.json \
    --candidate=artifacts/memory-cold-index/candidate-b-$profile.json \
    --output=artifacts/memory-cold-index/comparison-$profile.json
done
```

`ci-memory-cold-index` 执行该对照并上传原始／比较报告。基线专用于此次评分实验；修改基线、语料或等价预期须经审阅，不能机械替换为 main。不需要真实 API 密钥或付费服务。

## 保留历史正文加载实验

`ci-memory-capacity` 仍是历史已提交来源实验，现在明确固定**两个**端点：优化前 `760042683405760428688d1a7d7f0346e2ff77d3` 与优化后 `7739cb0f6d020e4e05d0bff8d9d18f59f3d903c0`。原始来源测量代码、严格的 17 项依赖对照、正文读取／事务断言和依据对照均不变。[历史报告](memory-capacity.zh-CN.md)保留原有数值与限制。

冻结该配对是为了避免无关的当前引擎改动改写历史正文加载实验，不是削弱当前测试：其余 CI 套件运行当前生产代码，新冷索引任务以自身固定基线测量本次评分改动。两个实验的结果不得相加或当作同一个端到端提速。

## 保留的边界

- 没有持久化索引快照：新的 Worker／索引仍构建完整索引；保留基线的重新验证不是磁盘恢复。
- 每次读取已提交来源仍加载存储的小说集合，来源序列化和修订核验没有被移除或用缓存绕过。
- 语义限制仍为 2,000 个合格片段及 32 MiB Float32 缓存。超过 2,000 时，当前嵌入明确回退本地检索，不暗中截断；本补丁没有新增全范围或仅候选子集语义模式。
- 文字／编号命中仍不验证可回答性。此处没有实现语义支持评估器或全书已披露范围自动候选抽取；已选来源的模型提议仍须作者审阅。
- 第二阶段章级正文持久化、编辑器扩展与共享摘要不在范围内。完成第三阶段四条有限工作线与共同门槛后，开始第四阶段授权工具 → 检索 → 草稿 → 作者审阅闭环，并明确步骤／时间／取消／审计限制。
