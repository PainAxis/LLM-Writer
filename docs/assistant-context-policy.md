# Assistant context policies

Each assistant chooses **Follow global** or **Custom** in its create/edit dialog. The global policy remains in System Settings. Custom mode controls token/message budgets, truncation versus rolling summary, summary threshold and retained original messages. User and assistant messages each count as one entry; a zero budget means unlimited in that dimension. The input-token budget includes the assembled persona, summary and messages; it is an estimate, rather than a provider tokenizer or model capability limit. Truncation removes older entries without shortening the current input. A persona/current input that cannot fit is rejected before an AI request, with the input kept for editing. Local conversation history remains complete in both strategies.

Rolling summaries persist their text together with `coveredThroughEntryId` and a policy fingerprint. Only originals through that committed entry can be replaced by summary text. A pending or failed background job leaves the previous cursor intact, and outgoing requests retain every original after it. Hard-budget requests first try to compact the uncovered interval; if it still cannot fit, sending is blocked instead of silently dropping unsummarized facts. Summary jobs send only newly folded originals after the cursor, plus the previous summary. Historical string-only summaries remain valid backup data, but have unknown coverage and are safely rebuilt from the complete original history before use. Clearing or replacing the history also makes a missing cursor unusable.

`contextPolicyMode` is optional for compatibility. Missing mode follows global settings even if a legacy assistant has the previously unused `contextPolicy` field. Only explicit `custom` mode activates that field. Normalization creates independent values, tolerates partial legacy data and bounds invalid numeric values. Cancelling the dialog leaves the saved policy unchanged.

`resolveAssistantContextPolicy` is used by the displayed budget, outgoing conversation context, post-reply summary generation and manual summary retry. Summary requests use the assistant's model override and an abort signal. Changing the effective policy clears that assistant's old summary and pending marker, preserves all original messages, and invalidates in-flight summaries. Global changes affect only assistants following global settings. Clearing/deleting conversations also aborts work and rejects late chunks/completions; deletion persists removal of the conversation.

Context preparation prevents duplicate sends while awaiting a summary decision. A summary request that loses ownership cannot restore cleared state or a pending marker. Backup v2 includes and validates the mode and policy; backups without a mode remain compatible.

The summary decision offers **Send originals** only if the assembled original context still fits its budget. Over-budget decisions offer **Retry summary** or **Cancel send**, allowing the input/budget to be adjusted; failed compaction never enables an over-budget request. If a background summary completes while the dialog is open, its latest text and coverage cursor are read together before assembling the request.

Assistant creation/edits, global policy changes and collection removals publish new state only after their synchronous local storage writes succeed. A later-key removal failure attempts to restore earlier writes. A user message and empty reply placeholder are saved in one snapshot before starting AI, so a failed initial save can be retried without duplicate messages or requests. If saving a completed or stopped reply fails, the visible reply stays in memory and the page offers **Retry conversation save**. This action retries storage only, blocks new sends until successful, and never calls the model again. Generated content is not durable until that retry succeeds; the warning asks the user to keep the page open.

Validation: `smoke:assistant-policy` exercises the real store with injected storage/transports (request payloads, per-assistant isolation, reload, compaction/retry, policy changes, late work, delayed/failed summary coverage, legacy rebuilding, final input budgets and initial/final storage failures). `smoke:compactor` checks persona/summary budgets and preservation of uncovered originals. Backup smoke accepts both legacy strings and cursor records and rejects malformed cursors. Chromium regression covers policy round-trips, editing cancellation, custom truncation, return to global settings, rolling-summary payloads and preservation of local history.

Conversation rendering is virtualized for long histories. Measured rows keep a stable reading position; incoming chunks follow the latest message only while the reader stays near the bottom. Home/End and the return-to-latest button navigate the history. The store retains every entry; virtualization does not change context budgets, summaries or backup data.
