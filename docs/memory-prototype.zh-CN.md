# 记忆检索原型

[English](memory-prototype.md) | [简体中文](memory-prototype.zh-CN.md)

入口：侧栏 **记忆检索 · 原型**（`#/memory`）。通过 `npm ci && npm run dev` 启动；生产版仍为静态网页，需 HTTPS 或 localhost 以计算内容 SHA-256。

这是第三阶段的技术原型，验证“修改旧章后排除旧事实、找回伏笔、避免未来剧情泄漏”。它尚不代表完整的长期记忆系统，也不代表第二阶段百万字编辑基础已经完成。

## 当前范围

- Orama 3.1.18 与官方中文 tokenizer，补充汉字 bigram 以改善陌生专名匹配；本地索引与检索在页面专属 Web Worker 中运行。
- 本地召回结合正文／章节标题 BM25，以及作者标记伏笔的原文／标签／别名。可选嵌入增加语义召回通道，各通道按名次融合（RRF）；可选重排对融合后的候选重新排序。
- 以章节列表的当前顺序作为披露顺序，在排名及向外部服务发送原文前检查作品和截止章节；结果展示前再次校验版本、精确原文范围和披露上界。
- 章节修订号取标题与纯文本正文的 SHA-256。伏笔标记同时绑定修订号与精确原文范围，改稿后不自动搬到新版本。
- 依据面板显示原文、章节、版本与 UTF-16 范围；界面使用文本插值，不把原文当 HTML 执行。
- 内置 80 章合成示例，可在原型中编辑并保存；示例独立存于 IndexedDB。实际小说每次检索前重新读取最新已提交正文，原型不写回实际小说。
- 外部服务均可选，默认关闭。本地检索不需要密钥，也不调用模型。

## 三项验收操作

1. **改旧章**：点击“查旧章事实”；在示例第一章把“银钥匙”改为“铜钥匙”，保存并重建后再查。依据应改为新正文和新修订号。搜索旧词时允许召回含共同词的新正文，但不能继续返回旧事实。
2. **找回伏笔**：点击“找回伏笔”，查询“接应信号”，披露范围设到第四十章。应找回第二章铜铃／西渡口的人工标记和对应原文。该别名是示例预先标记，不是模型自动识别出来的伏笔。
3. **防止未来泄漏**：点击“检查未来身份”，截止第十章时不应返回玄衣客真名；把截止章节改为第八十章后才可检索到。将范围缩回前文时，旧结果和依据立即清空。

实际小说按上述界面选取。需要修改正文时回到写作页保存，再回原型检索；尚未保存的编辑草稿不属于检索来源。

## 可选嵌入与重排

在记忆检索页面的服务设置中，可分别启用嵌入、重排，或同时启用。这里的设置独立于生成模型的 API 配置，两项服务默认都关闭。

| 设置 | 默认值及支持范围 |
| --- | --- |
| 嵌入协议 | Jina 或 OpenAI 兼容格式 |
| 嵌入端点 | `https://api.jina.ai/v1/embeddings`；填写完整端点 URL |
| 嵌入模型与维度 | `jina-embeddings-v3`、512 维；可按所选服务修改 |
| 重排端点 | `https://api.jina.ai/v1/rerank`；采用 Jina 兼容请求／响应格式 |
| 重排模型 | `jina-reranker-v2-base-multilingual`；可修改 |
| API 凭据 | 嵌入与重排分别填写 API 密钥 |

这些默认值可以修改，不保证每个账户都可使用对应模型。设置和凭据仅保留在当前路由会话中，不写入本地存储，也不进入备份；离开或刷新页面后清除。修改服务端点或协议会清除对应密钥。

启用服务后，执行检索会向所配置端点发送请求。嵌入请求包含查询和符合披露范围的正文片段；重排请求包含查询和符合范围的候选。超出截止章节的正文会在请求前排除。服务端点必须通过 CORS 允许应用所在的浏览器来源访问。远程端点须使用 HTTPS，本机开发端点可使用 HTTP。请填写最终接口地址，不含 URL 用户名／密码、查询参数或片段；请求不接受重定向。OpenAI 兼容嵌入服务须接受配置中的 `dimensions`，并返回带索引、维度完全一致的浮点向量。

嵌入最多处理披露范围内的 2,000 个片段，每批 32 个。如果符合范围的原文超过上限，语义检索会明确回退到本地检索，不会只悄悄处理一部分。重排最多接收融合后的 60 个候选。服务请求单次超时为 15 秒，远程请求总预算为 65 秒。

语义通道对符合范围的向量做精确余弦相似度扫描并排名。原文向量使用最多 2,000 条、32 MiB 向量数据的内存缓存，按原文修订号、服务、模型和维度配置隔离。符合条件的相同片段可复用缓存向量，查询每次重新嵌入。修改正文或嵌入配置不会复用不兼容的向量。缓存属于派生数据，不进入小说备份，并在页面生命周期结束时丢弃；也可通过清除缓存按钮提前清除。

服务失败时，本地关键词与伏笔检索仍可用，并明确显示回退提示。结果说明实际执行了哪些检索步骤。取消操作，或修改来源、查询、截止章节、服务设置，都会使未完成请求失效；迟到的服务响应不能恢复过期依据。

外部检索属于实验选项，上述三项本地验收无需启用它。服务回归测试使用确定性响应，不代表真实模型的语义效果或付费服务可用性已经通过验证。

## 版本与运行边界

关键词索引是内存中的派生数据，根据当前来源重建。本轮仍采用**整部作品重建**，未实现章级增量索引或索引快照持久化。同步开始即使旧索引不可用；若构建失败，检索会明确报错，不继续使用上一次的事实。索引构建版本和页面请求版本共同拒绝过期的异步结果。

所有依据均来自本次章节快照。当前不索引全书摘要、人物设定、世界观或外部资料，因为它们尚未具有逐条的披露范围和来源版本。作者提供的伏笔标签／别名视为在来源章已知的信息；它们仍须由作者保证不提前填写后文秘密。自动伏笔抽取、回收状态推断和事实关系图尚未实现。

原型并未改变已有 `writing_search` 工具或生成提示词；因此现有生成流程尚未获得这些防剧透保障。后续应在统一的来源范围协议稳定后接入这些入口。

示例本地数据不属于小说备份。重置示例只覆盖这个独立测试副本。纯本地模式不上传原文；启用外部检索服务后，会按上述范围发送查询和符合条件的原文。

## 验证命令

```bash
npm run smoke:memory
npm run smoke:memory-providers
npm run smoke:memory-hybrid
npm run build
npm run test:browser-memory
npm run test:browser-memory-hybrid
```

核心回归覆盖章节修改与删除、排序变化、作品隔离、陈旧伏笔、构建失败、并发快照，以及百万字符合成稿件。服务／混合检索回归检查请求格式、无效响应、语义融合、缓存复用、取消与回退。浏览器回归针对真实构建产物，覆盖示例交互、保存恢复、依据面板、已提交的实际小说读取，以及可选服务。项目配置总计 67 组冒烟测试、63 个浏览器场景；验证状态以审查提交的 CI 结果为准。合成数据与确定性服务响应验证的是工程边界，不代表真实小说的语义召回率。

如需运行可选的真实服务检查，在进程环境中设置 `JINA_API_KEY` 后执行：

```bash
npm run test:memory-live
```

该测试不属于 CI，会按所配置 Jina 账户消耗服务用量。它通过生产检索引擎和服务适配器处理三个合成章节，执行四项验收检查，预算上限为 20 次请求／30,000 个输入字符，不读取应用内保存的小说。结果摘要写入 `artifacts/memory-live/report.json`，不包含密钥。运行成功表示对应账户、模型在测试当时可用，不代表生产语义效果或全书容量已经得到验证。

**2026-10-04** 的 [Jina 实测记录](testing/memory-jina-2026-10-04.json)使用 `jina-embeddings-v3`（512 维）与 `jina-reranker-v2-base-multilingual`，四项检查全部通过，共 11 次请求、632 个输入字符。测试运行生产检索引擎和服务适配器；因环境中的原生 Node fetch 超时，使用临时本地 curl 请求桥接访问环境代理。尚未验证真实 Jina 服务的浏览器 CORS；浏览器回归使用本地合成服务。这次合成数据验收不代表语义质量或生产容量基准。
