## 产品边界与作者流程

Memory Lab 提供独立、默认关闭的扫描入口，处理所选作品从开头至披露截止章（含）的已保存正文。已有检索、全范围嵌入与支持检查授权不会启动本扫描。

1. 保存并同步正文，选择披露截止章，启用功能并生成**零请求预览**。预览显示作品、截止章、章数／字符数、A 的精确窗口数、服务／模型／端点、六维累计预算及单次上限。
2. 明确开始 A，逐窗从全部合格原文收集有出处的路由线索。A 不会自动启动 B。
3. 查看 B 预览后单独开始 B。预览显示保留线索、已枚举路由数量及累计最低调用数。B 惰性规划：singleton 原文集合最低数及当前已知任务均为下界，不是精确总数或剩余请求数。
4. 暂停、在硬限内追加授权、明确重试一个失败任务、明确跳过，或结束本批并审阅部分结果。审阅池满有实际出口：停止本批、逐条保存或忽略全部提议，再开新 segment 优先继续未处理 B，之后继续剩余 A。
5. 逐条审阅并保存或忽略。保存默认**尚未经作者确认**；在关系／伏笔列表确认是独立动作，为 Writer 选择与批准当前原文依据也是不同动作。

扫描不改正文、不确认提议、不选择／批准 Writer 依据、不运行工具或 Skills。没有自主检索、候选回灌循环或无人值守重启。空结果不证明关系、铺垫或回收不存在；伏笔候选不等于“从未回收”，可能回收也不是作者意图的证明。

## A：精确原文覆盖

规划器使用已保存章节顺序，不依赖数字 ID 或故事时间。截止章内每个非空章节切成连续原文原子，每个最多 1,000 UTF-16 单位。按实际 JSON 转义字符数与 UTF-8 字节上限确定性缩小原子，不归一化、不截断、不抽样、不拆代理对，也不跨章；空白与合法控制字符仍属于原文。

每个 A 窗口最多六个主原子，另加同章前后各至多一个原子作上下文。完整系统指令和序列化输入必须满足单次上限，必要时缩小主原子数量。主区间恰好把已披露正文覆盖一次；上下文重用只增加发送成本，不增加覆盖计数。空章保留独立覆盖记录。

A 返回严格的 version-1 JSON：零至四条 cue，每条包含一至四个逐字 key（各最多 80 UTF-16 单位）、一至两个唯一已提交引用，以及路由类型（`relation`、`setup`、`recovery`、`bridge` 或 `event`）。每个 key 必须逐字出现在引用原文中，每条 cue 至少引用一个主原子。这些只是路由提示，不是事实、摘要或统一别名；模型不能提供偏移、应用 ID 或确认标记。响应 `saturated` 时记录表示遗漏，不会静默补问更多 cue。

整个响应与当前来源校验成功后才推进 A 窗口。界面分别显示合格、已处理、剩余、跳过、失败字符／窗口及逐章修订。失败字符仍属于剩余工作，直到重试成功或明确跳过。`sourceCoverage: complete` 只表示全部主窗口成功，不表示所有语义事实已抽出。

## B：有限连接覆盖

B 只重读保留 cue 对应的精确原文原子，不接收 A 的断言、书名／章名、人物档案、已有图谱描述、摘要、未来章或隐藏别名。固定枚举：

- 每条 cue 的 singleton 单点。
- 按最早原文原子和 cue ID 排序后的每对连续 cue 及每组三个连续 cue。相邻指保留 cue 的相邻，不是任意相邻章节对；不要求共同逐字 key。
- 每个共享逐字 key 桶内的全部无序 cue 对，不限章节距离。
- 三 cue 共享 key 桥：中心 cue 分别与另外两个 cue 共享逐字 key。明确 A/B 别名原文可以提供两种 key，但路由本身不确立身份、因果或回收事实。

每个任务至多三个 cue，因此至多六个原文锚点。完全相同原文原子集合只发送一次，其路由计数归最先枚举到的路由。规划最多保留 65,536 个不同任务 ID，并在有界规划工作后让出执行。稠密同名桶可能在枚举全部组合前达到规划或时间上限。

`connectionCoverage: complete_for_contract` 表示保留 cue 的上述路由已枚举处理完，且没有跳过／失败任务、饱和或已记录连接缺口；它与 A 覆盖分开。最终 `reviewing_complete_for_contract` 还要求 A 完整覆盖。后续 A 批次增加 cue 时重新打开连接规划，之前的 B 完成不能代表新增 cue 已完成。

本合同**不承诺**没有共同逐字 key 且不相邻的远距纯语义联系、A 未产出的 cue／必要 key、任意四个以上 cue 的链、超出提交窗口的上下文，或仅在未来章才揭露的别名。原文全覆盖不等于任意关系完整性。冻结评估在分母内保留这些能力遗漏。

## 预算与有限容量

全部六维在同一 campaign 的 A、B、重试与跨批过程中累计。追加授权只增不减、绑定身份、按 grant ID 幂等；继续与新 segment 均不归零。

| 维度 | 默认授权 | campaign 硬上限 |
| --- | ---: | ---: |
| 请求尝试数 | 64 | 4,096 |
| 活跃处理时间，毫秒 | 65,000 | 3,600,000 |
| 系统指令＋序列化输入，UTF-16 单位 | 1,024,000 | 65,536,000 |
| 系统指令＋序列化输入，UTF-8 字节 | 3,072,000 | 196,608,000 |
| 预留输出 tokens | 76,800 | 4,915,200 |
| 预留响应字节 | 4,194,304 | 268,435,456 |

调用服务前先预留一次尝试、精确序列化输入、1,200 输出 tokens 与 65,536 响应字节，失败尝试也计入。实际观察到的响应字节与尝试发送的原文字符另列。预留不是实际 Token 消耗、金额上限或服务商账单。扫描活跃时间账本涵盖引擎规划、扫描／续扫 guard、请求、解析及发布处理，不含静置或等待作者决定的时间。下一 segment 的 input builder 在引擎有界活跃操作中惰性执行，其已提交来源／读库准备计入扫描 `activeMs`，不是记账开始前先完成。引擎准备（`preparationMs`）与明确触发的本地审阅核验（`reviewMs`）另列观测，不扣扫描 `activeMs`，也不是新后台授权。引擎审阅 guard 仍有 10 秒上限，因此扫描额度耗尽不阻断本地审阅／保存。保存调用引擎审阅 guard 和明确的保存前 `audit`，均计入 `reviewMs`；只有实际 own-CAS 返回才推进基线并执行保存后校验。整个 UI 保存流程的外层期限为 10 秒。引擎操作之外的 UI 展示及图谱读写不含在引擎计时内。

单次上限：8,000 原文单位、16,000 系统指令＋JSON 单位、48,000 UTF-8 字节、1,200 输出 tokens、65,536 解码后响应字节及至多 30 秒。生产 bounded SDK 适配器只允许一次尝试，没有隐藏重试、重定向、流式、历史、工具或正文用量日志。截断输出、无效 JSON、重复／多余字段、伪造引用及超大响应使整个任务失败。

其他边界：

- 引擎准备与每次引擎来源 guard：10 秒；待开始预览最长五分钟；整个 campaign 含暂停最长一小时。
- 每 segment cue 容量默认 2,048，可明确增加至 8,192；campaign 保留出处索引另受 8,192 cue 及 16 MiB 序列化 cue／锚点数据限制。
- 审阅池：512 候选及 8 MiB 序列化载荷。调用前预留最多四条 A cue 或两条 B 候选，不淘汰已有内容。
- 遗漏账本：最多 128 条明细，加三个按范围类型分类的溢出下界。适用时记录来源章／修订／区间／窗口，或连接路由／任务／原子及 segment，不记录正文。

这些是应用载荷／规划上限，**不是浏览器／进程总内存上限**。正文快照、原子、校验及其他运行对象还会占内存。反复读取已提交正文与哈希仍是长篇真实成本；本条不重构第二阶段存储。

## 暂停、失败与跨批继续

常规流程为 `ready_a → running_a → ready_b → running_b → reviewing_*`，另有明确的暂停和终止状态。开始／推进共用执行中 promise，重复点击不会增加重复请求。每次 advance 最多执行一个服务任务；界面只在已授权且运行中持续推进。

暂停等当前有界请求完成；取消中止请求、撤销 campaign 并清除未保存提议。取消不能撤回已派发请求，也不能证明零费用。服务／协议失败保留失败任务，要求明确重试或跳过；重试是新计费尝试，不是无限自动重试授权。迟到响应不能推进覆盖或出现为候选。来源／归属／配置／图谱变化、过期与来源校验超时会使会话失效，不能回退旧提议。

审阅池满时结束本批并逐条处理。全部保存或忽略后，`nextSegment` 验证同一来源、披露、配置及已知图谱基线，产生新 segment／generation，保留 campaign 账本、正文覆盖、有界出处索引、已完成任务集合与 B 独立游标。**即使 A 已覆盖 100%，未完 B 仍继续，绝不重发已完成 B。** 该 B 计划结束后再提供剩余 A。跨批保留的失败工作仍须明确重试／跳过。

出处索引满不能静默淘汰；明确跳过剩余 A 范围会记录来源区间和连接缺口。规划容量是 campaign 硬停止点，不能通过新 segment 或追加预算绕过。饱和与真实容量跳过保持 partial；普通 512 满池分批本身不是永久遗漏，也不是重新开始 B 的理由。

重新预览意味着**新 campaign 与新授权**，不是续批。当前路由内保留累计已用成本及原文发送尝试，并保存最近八次已结束 campaign 的账本和停止原因。停止时快照不是最终服务商账单，不接收迟到响应正文，且不含正文、模型内容或凭据。导航／刷新会丢弃会话、中间 cue／提议及路由历史；没有跨刷新续扫或可恢复历史账本，历史消失不能代表此前零成本。

## 来源安全、审阅与图谱 v2

静置、暂停或审阅时不定时轮询整本正文。可见预览／候选／伏笔条目是上次核验快照，操作之间可能变旧；未捕获外部改动不代表当前已校验。明确的来源／配置／storage／focus 事件会使相关会话失效。在派发前、异步响应后、接受 checkpoint／发布前、展开依据时及保存前后，操作 guard 重新读取已提交来源及预期图谱修订。独立校验的章节修订、精确 UTF-16 区间／原文、披露与归属必须一致；检测并发已提交改稿不依赖 storage 事件。最终 guard 成功才发布候选；该校验预算耗尽只能暂停，不能先显示未经核验的成功结果。

关系候选保留全部支持锚点与模型的 `explicit`／`inferred` 标记。伏笔使用有类型的 `setup_candidate` 或 `possible_recovery`，保存每个 `setup`、`recovery`、`context` 前提；可能回收必须同时有铺垫和回收。campaign／segment／job／candidate provenance 由应用分配。`semanticValidation: protocol-and-current-sources` 只验证协议与引用新鲜度，**不验证含义或正确性**。

每次明确保存使用原有图谱 compare-and-swap（CAS）。只有自己的实际成功保存返回的新修订能推进审阅基线，无关图谱写入会使剩余提议失效。相同内容加全部锚点的精确重复条目不重复写入。失败或不确定保存不提示成功，不得盲目重写。若保存提交后来源才失效，作者数据仍存储，但过期依据隐藏，不自动删除。小说存储与图谱 CAS 是两个事务，不是跨数据域原子保存。

图谱文档升为 version 2，同时保留 `relations` 与 `plotLinks`：

- 有效 v1 读取时仅在**内存中**补空 `plotLinks`，不改写存储；明确保存才写 v2，继续使用原存储 key。
- 普通关系与伏笔保存保留另一数组。伏笔完整保存所有有类型前提、原文、范围、修订及 provenance。上限明确为 10,000 关系、2,000 伏笔条目、8,000,000 引用总单位及 24,000,000 序列化文档单位。
- 未知未来版本属于 `unsupported-version`，不是损坏的旧数据。读取、保存、导入、备份、恢复均拒绝，不覆盖已有图谱字节。明确恢复可修复损坏／无效的已知版本数据，不能覆盖不支持的未来 schema。
- 备份／导出不因当前不可见而丢弃作者标注；恢复使用 CAS 和新图谱修订。规范化导出不静默迁移已存 v1。
- 观察到来源／披露变化或下一次操作重验时，旧引用章节改稿或披露范围缩小会使过期／未披露前提对应的整条关系／伏笔隐藏。作者确认不能绕过，也不能改变最初推断标记。

已保存伏笔面板展示上次核验原文，操作前重验，提供独立确认和删除；搜索／展示最多 200 条。候选审阅每页 20 条，章节覆盖每页 50 章。plotLinks 和模型解释不是 Writer 依据。正文生成、续写、润色继续分别要求另行选择／批准当前已披露原文，扫描结果不会自动进入任一提示词。
