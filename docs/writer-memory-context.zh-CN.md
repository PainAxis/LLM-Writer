# Writer 中带原文依据的写作记忆

[English](writer-memory-context.md) | [简体中文](writer-memory-context.zh-CN.md)

本轮属于第三阶段，将已披露的小说依据接入 Writer 生成流程。不引入第四阶段 Agent、自主工具调用或自动图谱提取。

## 使用方法

在 Writer 的**章节正文生成**、**续写**或**润色**中，勾选**使用记忆检索依据**，默认关闭。输入要查找的事实或伏笔，选择**已披露至**，再点击**检索并预览**。截止章不能超过实际正在写作的章节。

所有候选默认不选中。核对原文片段、章节修订号、匹配提示及原文明示／模型推断／作者确认标识，逐项选择原文或完整关系后，再点击**已核对，将所选依据用于本次生成**。只有所选项进入生成依据块。启用记忆后，须完成这次核对才能生成；空选择不能批准。修改选择、查询、截止范围或来源会清除之前的批准。匹配提示始终不验证是否有答案，详见[依据逐项核对](memory-evidence-review.zh-CN.md)。生成及应用结果仍使用 Writer 原有操作。

若另一标签页修改同一部小说并保存，之前的预览将失效。原有保存冲突保护也可能阻止再次检索：先复制未保存草稿，刷新并重新打开作品，合并草稿后保存，再重新检索依据。检索不会覆盖另一标签页的修改；详见[持久化协调](persistence-coordination.md)。

披露限制约束本次检索追加的依据。手动填写的写作要求、大纲及手选已有素材仍按各自原流程使用，不会追溯清除其中的后续剧情信息。

## 来源与披露规则

依据来自当前已保存的小说，而非从记忆检索页复制后独立存在的结果。准备过程读取已提交章节，将范围限制到选定的披露截止章，再把此前缀同步到本地检索索引。披露按章节当前排列顺序判断，不按故事发生时间或章节 ID 判断。

检索片段保留章节 ID、标题、SHA-256 原文修订号、UTF-16 原文范围和精确引用。纳入上下文的图谱关系保留最初的原文明示／模型推断类别、作者／模型录入来源及作者确认状态。关系的每个前提都必须对应当前版本、且已披露的正文。作者确认不能使过期依据重新有效，也不能提前开放后文前提。

自由填写的标注文字不会自动被当成有原文依据。如果关系谓词没有逐字出现在某一条引用中，预览和生成依据改用中性标识**原文关联**或**待核对推断**；伏笔标签同样使用通用标识。这防止作者把后文身份写进一个原本有效的早期标注后绕过披露边界；已保存的图谱标注本身不会被改写。

准备完成后和实际发送生成请求前都会再次检查来源快照。修改旧章、重排或删除章节、修改图谱以及已提交来源读取失败，都会阻止发送先前准备的依据。作者需基于当前来源重新准备；旧引用不会悄悄改绑到新正文。 生成模型每次实际 HTTP 发送（包括 SDK 自动重试）也会执行校验，并在接受生成完成结果前再次核对。续写／润色在首次修改编辑器前检查，全文替换确认框结束后仍要重新检查；保存失败会保留已应用草稿供重试，不重复插入。准备阶段取消后不能迟到启动模型请求。外部服务已收到的数据无法撤回，生成正文仍须作者审阅。

## 上下文预算

Writer 界面使用 **6,000 UTF-16 字符**的依据预算；底层服务接受 **1,000–16,000 字符**。预算约束整个追加的依据区块，包含说明文字和来源元数据。系统先将可完整容纳的来源单元纳入有界预览，再由作者选择需要的项目；不会截断引用后仍把它描述成原先的精确原文范围。因此，预算可能有剩余空间，也可能排除放不下的候选。

这只是新增依据区块的上限，不保证完整请求适合所有模型的上下文窗口。原有写作任务、用户选定的素材、模型输出预留和服务商限制也会占用上下文。来源有效并不等于它能回答问题；把模型推断放入提示词也不会将其升级为原文明示的事实。

首次准备仍需为已披露正文建立索引；来源不变时再次准备可以复用。缩小披露前缀后再次扩大，可能需要重新索引大量正文。最终追加区块很小，不代表超长篇的准备成本也很低。

## 可选外部检索

本地关键词与伏笔检索无需检索 API。可选嵌入和重排分别控制，默认均关闭。开启后执行检索，会把查询与已披露范围内的候选正文发往所填服务；服务须支持浏览器 CORS，可能产生费用。开始生成时仍使用正常的写作模型 API。

嵌入／重排设置和密钥只保留在当前 Writer 页面会话，不写入小说或备份。修改服务地址或协议会清除对应密钥。每批正文嵌入、查询嵌入和重排请求在发送前都会复查已提交来源。来源变化会阻止操作；普通服务故障则明确提示回退本地检索，回退后的依据仍需核对。

## 复现容量检查

```bash
node --expose-gc --import tsx scripts/stress-writer-memory.ts
node --expose-gc --import tsx scripts/stress-writer-memory.ts --profile=million
node --expose-gc --import tsx scripts/stress-writer-memory.ts --profile=ten-million
```

两档确定性中文小说素材分别包含 **600 章／144 万 UTF-16 字符**和 **2,500 章／1,050 万字符**，图谱分别包含 **1,801** 和 **7,501** 条关系。后期关系特意排列在早期关系之前，用于检查来源有效性和披露过滤是否先于输出数量限制执行。

测试使用真实记忆索引与 Writer 依据准备服务，检查分布于全书的精确来源检索、跨卷伏笔别名、不同依据预算、已确认的多前提推断、后文身份揭晓、旧章修改、批量改稿、重排与删章，以及发送前来源／图谱变化。受控重排适配器核对待发送片段，并拦截发送前来源变化的竞争场景，不调用真实服务。原文核验次数、依据区块长度、准备耗时、索引同步工作量和内存测量保存在 `artifacts/writer-memory-stress/`。

容量测试继续单列 24 道中文／代码混合查询。历史 PR #34 实现中，`白银封蜡FS00001` 可能让仅匹配通用中文词的短片段挤掉精确来源，而单独查询 `FS00001` 能找回。[混合查询后续修复](memory-mixed-query-recall.zh-CN.md)调整了本地候选及排序通道，每档另加 24 次使用原始完整问题、关闭图谱与远程检索的硬性断言；原有 68 次准备及混合查询行保留，用于对照。

[依据审阅后续工作](memory-evidence-review.zh-CN.md)保留原有 12 组／92 次准备检查点，再追加无答案边界和明确选择验收；选择操作与准备次数分开计数。

每档规模使用独立 Node 进程，并用内存中的已提交来源适配器供稿。这些测试验证合成素材的来源完整性与容量，不评估文学质量或真实模型质量。Node 测量不包含浏览器 IndexedDB 正文读取、Worker 序列化、编辑器渲染和实体设备行为；单次耗时受机器环境影响。采样堆内存可能遗漏同步操作中的峰值，因此另报进程最大 RSS。无需调用付费模型。

## 历史 PR #34 本地实测记录 — 2026-10-08

两档均通过 **11 组场景、各 68 次成功准备**，合计 **136 次准备、778 次精确来源核验**，真实外部请求为 0。每档发送一次模拟重排请求，并在来源变化后拦截下一次请求。接受报告前已核对生产源码与测试脚本的校验和。

| 600 章／144 万字符／1,801 条关系 | 8.55 秒 | 95／111 毫秒 | 5,930 字符 | 878 MiB |
