# 检索依据的逐项核对

[English](memory-evidence-review.md) | [简体中文](memory-evidence-review.zh-CN.md)

本轮第三阶段区分“找到了当前原文”和“问题有了答案”。记忆检索页与 Writer 展示确定性的文字匹配信号；Writer 要求作者逐项选择原文或完整关系后，再批准用于生成。不会把检索分数换算成置信度，原有标识在所有状态仍保持 `answerability: unverified`；下述独立的可选模型支持面板不会替代这项约定。

## 标识的含义

| 状态 | 含义 | 不能据此证明 |
| --- | --- | --- |
| `none` | 本次结果或当前所选范围中没有合格依据。 | 整本小说都没有答案。 |
| `candidates` | 存在合格依据，但所检查字段没有完整查询或请求编号匹配。 | 候选一定不相关，或不能帮助写作。 |
| `matched` | 至少一个字段包含完整查询或一个请求的精确编号。 | 原文回答了问题、全部请求编号都已找到，或所问事件确实发生。 |

信号区分引用原文、章节标题与作者伏笔标签／别名；标题或标注匹配不等于引用正文匹配。精确编号沿用[既有 ASCII 代码规则](memory-mixed-query-recall.zh-CN.md)。`requestedIdentifiers` 与 `missingIdentifiers` 说明当前候选或所选依据覆盖及缺少哪些请求编号。一个编号存在、另一个不存在的查询，可以处于 `matched`，同时明确列出缺失编号。

这些信号来自当前已披露来源，不使用服务分数或数字相关性阈值。可选语义检索与重排可以找出或重排候选，但不会核实可回答性。原文逐字写下一个尚无答案的问题，也可能显示 `matched`；已有物件编号加上一个从未陈述事件的问题，同样可能显示 `matched`，两者仍未验证有答案。

图谱评估使用所选关系的全部原文前提，不会把作者谓词或推断关系升级为原文明示事实。原有出处、作者确认状态、章节修订与披露约束继续保留。

## 在 Writer 中选择依据

打开章节正文生成、续写或润色，启用记忆检索，选择披露截止章并检索。所有返回原文及关系都**默认不选中**，完整文字／编号命中也一样。查看精确原文和匹配信号，再逐项选择本次生成需要的正文或完整关系。选择关系时包含全部前提，不能删去其中一个前提，把原本不合格的推断变成有效依据。

只有所选项进入生成依据块。评估会基于最终所选项重新计算；去掉唯一编号命中后，`matched` 可能变为 `candidates`，并重新提示缺失编号。空选择生成空依据块，不能批准。批准记录的是作者选择的上下文，不是已经验证的答案。

修改选择会撤销之前的批准及待发送生成许可。查询、截止范围、原文和图谱变更继续触发既有失效规则；批准、模型发送、完成和应用生成内容仍需当前已提交来源有效。选择操作只读取私有的、经过验证且受预算约束的候选快照，修改返回的预览对象不能伪造原文依据。不存在或重复的选择 ID 会被拒绝。

Writer 原有 6,000 字符依据预算包含元数据和指令，服务支持 1,000–16,000 个 UTF-16 字符。选择不会扩大预览的有界候选集合，也不会截断原文引用；它不产生新的嵌入或重排请求。这些服务仍须单独主动开启，密钥仅留在当前页面会话。

## 独立的可选模型支持意见

[可选引用支持核对](memory-support-checks.zh-CN.md) 已接入 Memory Lab 与三个 Writer 入口，并在 [PR #40 验收并合并](testing/memory-support-checks-2026-10-22/ACCEPTANCE.zh-CN.md)。选定当前已披露原文（或所选关系的全部前提）后，作者可准备纯本地预览，再明确启动有界聊天请求；检索／服务商授权不会连带批准该请求。独立面板显示 `supported`、`insufficient` 或 `uncertain`，逐项前提附原文引用；协议／来源校验不能证明语义蕴含，意见和评分都不是置信度。未运行、取消、过期、不可用或失败仍为未验证，不是假装成功的“不足”。

启动 Writer 核对会撤销旧生成批准。任何结果都不会自动选择或批准依据，核对答案／解释也不进入写作提示词或正文。生成前，作者仍须明确批准所选且重新校验为当前有效的原文；预算、失效和失败行为见所链接说明，不能从旧匹配标识推定这些保证。

当前配置动态聚合全部已注册冒烟测试。支持核对另有必要的 `ci-memory-support` 任务，包含 52 个浏览器场景，有意不加入旧 `test:browser` 聚合，以免重复执行。它覆盖冻结的 25 个语义用例，另加 600 章／1,388,902 字符的 Memory Lab 与三个 Writer 入口场景，后者不改变语义分母。浏览器验收已在所链接 #40 准确修订的 CI 完成，没有本地 Chromium 执行；后续 head 须通过自身必要检查。下方带日期的测量保持为历史依据审阅记录，不是新的支持核对或真实模型结果。

## 回归与测量口径

Writer 压力运行器保留原有 PR #34 的 11 组／68 次准备检查点，以及 PR #35 的 12 组／92 次准备检查点，再追加依据审阅验收。历史原始报告保持不变。新增情况覆盖普通中文部分匹配、不存在及部分命中的编号、逐字出现却未解答的问题、已存在主题但未陈述的事件、旧章改稿、未来编号、仅所选项评估、空选择及完整多前提关系。选择操作与检索准备分开计数。

```bash
npm run smoke:memory-match-signals
npm run smoke:writer-memory-selection
node --expose-gc --import tsx scripts/stress-writer-memory.ts
npm run test:browser-writer-memory
```

原始两档语料分别为 600 章／144 万，以及 2,500 章／1,050 万 UTF-16 字符。审阅组只在历史检查点之后追加一个明确未解答的问题，增加的字符数单独记录。章节修订、精确范围、披露限制、完整依据预算和真实外部请求为零继续作为硬性断言。这些测试验证已知合成边界，不是无答案识别率或生成写作质量测量。

## 本地实测记录 — 2026-10-08

两档均通过 **13 组、103 次准备和 7 次成功选择**，每档另拒绝一次旧来源被修改后的选择。合计 **206 次准备、14 次选择、1,159 条来源检查，真实外部请求为零**；原有受控重排测试每档调用一次模拟服务，并阻止来源过期后的下一次请求。每档 24 次混合查询正文检查和 24 次关闭图谱检查仍全部通过。

每档记录的九种评估情况区分不存在／已删除／未来编号（`none`），普通中文或缺失编号回退（`candidates`），以及部分编号、已有主题、原文问题和修订编号匹配（`matched`）。每种情况和所选结果始终保留 `answerability: unverified`。去掉唯一匹配片段后，选择评估重新变成 `candidates`；空选择为 `none`。原文未解答问题只在原有 92 次准备检查点之后追加，共 **43 字符**。

| 原始规模 | 冷准备 | 热准备 p50／p95 | 进程峰值 RSS | 最大预览／所选依据块 |
| --- | ---: | ---: | ---: | ---: |
| 600 章／144 万字符 | 10.32 秒 | 106／125 毫秒 | 887 MiB | 5,684／1,995 字符 |
| 2,500 章／1,050 万字符 | 64.84 秒 | 622／690 毫秒 | 2,252 MiB | 5,881／2,000 字符 |

依据块最大值来自受测的 6,000 字符准备及七次明确选择；所选块较小反映这些选择，不代表服务预算缩小。热准备取首次冷调用后的原有 24 次唯一标识查询。这些是单次测量；评估元数据改变了序列化内容，因此历史工作负载检查点不构成孤立提速实验。大档冷准备仍约 65 秒，进程峰值内存约 2.2 GiB。

[审阅记录](testing/memory-evidence-review-2026-10-08/review.json)保留命令、环境、来源／辅助模块／测试的 SHA-256、两处历史工作负载检查点、全部 24 道召回结果、评估状态及所选 ID。原有 92 次查询／截止范围／预算组合及前 12 个场景名称已与 PR #35 原始运行逐项比对，历史报告未重写。完整原始结果可由上述命令复现，并输出为 CI 产物。

PR #36 验证集包含 **79 组冒烟／133 个浏览器场景**，其中 Writer 记忆 **20 个场景**；基于测量的来源读取后续工作见[索引与语义容量](memory-capacity.zh-CN.md)，当前配置覆盖见[目录结构](../PROJECT_STRUCTURE.zh-CN.md#校验与发布)。浏览器验收覆盖实际预览选择、批准和捕获的模型请求；其 CI 结果需与这些 Node 结果分别核对。

这些历史 Node 测量不包含浏览器存储加载、Worker 传输、编辑器布局、真实设备和实际服务延迟；它们测量审阅行为，没有解决当时观察到的容量成本。后续[正文加载](memory-capacity.zh-CN.md)、[冷索引](memory-cold-index.zh-CN.md)及[全范围扫描](memory-full-range-semantics.zh-CN.md)是独立工作。当前验收与交付状态以[四轨路线图](../ROADMAP.zh-CN.md#第三阶段完成契约)为准，不由上方历史测量代表。支持核对与候选扫描分别保留证据；第四阶段实施须通过共同最终 head 审阅／CI 及实际合并／main 门槛。第二阶段持久化／编辑继续独立。
