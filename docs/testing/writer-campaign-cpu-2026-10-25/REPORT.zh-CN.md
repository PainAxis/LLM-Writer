Node 中文测试在正文 966,686 个字符、120 个已提交任务、121 次固定测试调用和 486 笔已提交操作时出现 `operation_timeout`。仍保留一项未解决分配，余额 1,927,388 字节，账本不匹配为零。失败步骤的 14,014 毫秒包含错误处理和恢复；原报告没有采集到底由 3 秒单操作期限还是剩余 10 秒动作期限触发，因此准确期限归因是“未采集”，不能推断。

## 修正边界

- 在既有有界历史读取批次中，复用同一条准确原始字符串的字节数，用于写入账本及保留量校验。公共解析器仍独立测量和验证输入；不信任调用者提供的长度，不跨读取缓存，不跳过原始字节、哈希或上下文验证。
- 一次账本操作只计算一次不可变请求的额度几何，再由该已验证结果推导既有阶段和未来义务。未知、取消、脱离当前索引和失败请求都不退款。
- 最终写入条目校验中复用刚测得的值长度，保留独立最终序列化测量。
- 增加有界、无正文、基于单调时钟的超时观察，区分实际选中的单操作/动作期限及阶段。诊断不增加权限、不改变结果、不持久化，也不泄露载荷。

这是 CPU 和诊断修正，不是减少仓库 IO。历史读取顺序、最终 head/catalog/successor 校验、规范格式、SHA-256 身份、账本转换、CAS 及所有既有限制均保留。本轮不实施新的规划/canon 功能。

## 有界诊断语义

引擎本地 getter 返回分离副本，最多八项事件及饱和溢出计数。事件只含固定阶段、timer/动作检查触发类型、单操作/动作/相等期限选择、配置上限及单调时钟的已用/剩余时间。timer 的时间在同步 abort 监听器之前采样，但只有原超时真正胜出且完成原有 settle/abort 后才保留事件；诊断失败不改变运行结果。阶段表示在哪里观察到到期，不一定表示之前哪段 CPU 工作耗尽时间。没有回调、持久 trace 或含正文的标识符。

新存储报告使用 schema 2。严格校验的旧 schema 1 可投影为带明确 `not_collected` 诊断的派生 schema 2，这不为历史证据补造观察。采集器存在但没有保留事件时是 `not_observed`，不能据此保证绝无超时。未知字段、原错误或含正文的载荷均拒绝。

## 定向检查

冻结旧记账实现与候选在 3,113 次比较中相同，包括 602 次相同拒绝；另核验 18 次实际字节写入、六次完整读取序列和 24 次原始记录损坏拒绝。单次 apply 的 UTF-8 编码次数在 reserve 中由六次变为两次，其他请求阶段由四次变为两次；事件原始字符串仍在有界批次入口和公共解析器中各测一次。这是工作次数观察，不是已证明的时延改善。

独立审阅者复跑 CPU oracle、记账、read-batches、存储、engine（44 例）、UI 和超时诊断（15 例）套件通过。实现阶段的封闭报告套件通过 89 项检查。这些定向结果不替代下方完整门槛。

首次严格类型检查发现新 CPU smoke 辅助函数返回类型过宽；仅收窄注解以排除 `create`，编译输出 JavaScript 逐字节不变。原失败日志和清单已保留，随后完整 lint／类型／构建／122 组测试全部通过；最终 464 个原生路径的前后清单完全一致。
