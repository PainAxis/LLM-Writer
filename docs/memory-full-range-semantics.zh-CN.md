## 改变与不变的部分

- 全范围扫描、嵌入和重排默认均关闭。服务配置、密钥与扫描决定仅留在当前路由会话。
- 未提供 `MemoryRemoteOptions.fullScan` 时，普通路径不变：启用的嵌入可覆盖最多 2,000 个合格片段；超出后，语义检索回退到完整的本地关键词、精确编号与作者伏笔通道，**不发送任何嵌入请求**。单独启用的重排保留原行为，因此零嵌入请求不等于零外部请求。
- 明确提供 `fullScan: { maxCalls, maxActiveMs }` 后，**任何语料规模**都使用有预算的扫描协议，包括不超过 2,000 个片段的情况。不能因语料较小而忽略明确请求的预算。
- “全范围”指截至所选披露截止章（含该章）的当前合格原文块，不包含未来章节、旧修订、隐藏来源，也不代表全部可能答案。既有本地伏笔／编号通道保留，不被语义短名单替代。
- 缓存仍同时受 2,000 条和 32 MiB Float32 向量载荷限制。扫描可覆盖超过 2,000 个片段，而不同时保留全部向量；这两项限制都不是进程总内存承诺。

## 作者操作流程

Memory Lab 与 Writer 写作记忆使用同一套控件。

1. 选择已提交的作品、查询与披露截止章。单独启用嵌入服务，再打开“**扫描全部已披露原文块**”；重排仍需单独选择。
2. 核对累计调用尝试次数和处理时间。界面初始默认值为 **160 次尝试、65 秒**；5 分钟或 10 分钟必须明确选择，不会暗中延长。
3. 点击“**准备扫描计划**”。本地准备展示精确的合格／有效缓存／待嵌入片段数、原文字符估计，以及冷缓存／当前缓存的预计调用数。此步骤**不请求查询嵌入、正文嵌入或重排服务**，也不提供可选择的依据。
4. 核对后点击“**开始扫描**”。预算或服务暂停时，可明确继续／重试、追加预算、使用本地结果或取消。进度显示已评分／合格片段、已尝试／已授权调用，以及已用／已授权处理时间。
5. 完成后核对精确的当前来源。在 Writer 中，仍须逐项选择并批准要使用的片段或完整关系。启动或延长扫描不等于批准依据，不授权生成或修改正文。

处理期间和等待决定期间均可取消。编辑来源、修改查询、披露范围或服务配置会撤销旧操作。继续暂停的扫描不会重新执行 Writer 准备、保存／同步作品，也不会暗中从头开始。

### 停止扫描并使用本地结果

“**使用本地结果**”停止后续全部远程请求，包括重排，丢弃**全部**未完成语义贡献，并在重新核验来源后只返回原有本地通道结果。部分语义分数不会混入结果。来源校验拒绝、过期或超时属于失败，不能包装成成功的本地回退。

来源校验本身也消耗处理时间。处理时间预算耗尽时，“使用本地结果”会禁用，因为当前授权不足以再做校验。可以明确追加时间继续；若只需本地结果，应**取消扫描，关闭嵌入和重排，再发起新的本地查询**。这是新操作，不是暗中重置旧预算。若仅耗尽调用次数，而处理时间仍充足，则仍可使用本地结果。

## 预算与会话契约

权威累计值属于一个私有 Worker 会话和一个逻辑 `MemoryClient.search` Promise。传输分页是实现边界，不是新的作者授权。

| 边界 | 含义 |
| --- | --- |
| 界面初始预算 | 160 次调用尝试、65,000 ms 处理时间 |
| 明确时间选项 | 65 秒、5 分钟或 10 分钟 |
| 累计硬上限 | 4,096 次调用尝试、3,600,000 ms 处理时间 |
| 单次处理页 | 最多 8 次调用尝试、50 秒处理额度 |
| 超时后备限制 | 单次服务请求 15 秒、来源校验 30 秒、Worker RPC 90 秒；普通引擎原有的 65 秒上限不提高 |
| 绝对寿命 | 自会话创建起 1 小时，包含等待作者决定的时间 |

初始预算必须为正安全整数，在外部操作前完成校验。追加授权携带当前会话／代次和授权 ID，新增调用数／时间为非负整数。零追加的继续操作仅明确允许在剩余额度内重试，不代表无限授权。相同重复授权幂等处理；冲突重复和过期标识失败，不会只修改一部分累计值。分页和重试均不重置累计台账。

查询嵌入、正文嵌入、重排、失败的适配器调用及重试，均在调用适配器**之前**计入尝试次数。该数值不是已确认的网络发送、计费请求、Token 或金额。计划为启用的重排预留调用估计，重排也消耗同一总预算；进入重排阶段却无剩余额度时先暂停，不擅自请求。

处理时间包括扫描本地准备、评分、来源校验和服务等待，不包括等待作者决定的时间；暂停等待不能延长固定的一小时有效期。扫描创建前的初次来源加载／索引同步属于另外的开销，因此端到端实际等待时间可能长于处理时间预算。分页限制约束进行中的工作，不是浏览器调度或总耗时保证。

客户端会处理并结束缺失／抛错的决定回调、回调拒绝、取消、新检索、同步／失效、销毁、Worker 错误、RPC 超时及绝对到期。没有决定回调时，立即选择经过来源校验的纯本地结束路径，不自动开始远程扫描，也不无限等待；校验无法安全完成则拒绝 Promise。迟到的回调或响应不能复活已取消会话。Worker 丢失、刷新和离开页面后没有持久化检查点，也不会自动续扫／重启。

## 流式处理、缓存与来源新鲜度

引擎先嵌入查询，再**为全部合格有效缓存评分，之后才插入缺失项**，避免尚未使用的缓存先被新条目淘汰。未覆盖原文每批最多 32 个；整批响应通过验证后才修改覆盖位图、缓存和游标。格式损坏或失败批次不提交部分覆盖，明确重试会再消耗一次尝试。

检查点保留一个查询向量、覆盖位图、游标／计数器，以及仅语义前 `min(limit * 4, 200)` 项的 ID／分数，不保留全部原文向量矩阵。只有完整覆盖后，语义贡献才进入原有的余弦排序、同分规则和本地关键词／编号／伏笔融合。可选重排位于融合之后，仍受同一明确授权额度约束。缓存键绑定当前来源身份和服务配置；缩小披露范围不能借缓存重新引入未来章节。

每次外部查询、正文及重排请求之前、异步响应返回后，以及最终依据发布前，都会核验当前来源与操作归属。Memory Lab 重新读取已提交来源；Writer 保留已提交来源／图谱校验和选择／批准流程。旧章改动、索引替换、保存失败及并发来源变化不能因为先前授权过扫描而被接受。

进度和诊断只暴露安全计数／状态，不含服务响应正文、凭据、凭据哈希、向量、中间 Top-K 或原文预览。未完成页面不提供最终依据。完成全范围语义评分后，每个结果的 `answerability` 仍为 **unverified（未验证）**；没有返回结果也不证明全文没有答案。

## 为什么选择全覆盖，而不是候选路由

该选择解决覆盖问题，不是基于新测得的模型准确率优势。实施前筛选始终保留同一份 4,096 片段合成语料、46 个独立正例查询及其 62 条必要前提：

- 固定的一半本地／一半范围采样候选池，在 64、128、256 个候选下，包含全部必要前提的查询只有 **0/46、0/46、1/46**。
- 手工英中词典扩展查询后提升为 **23/46、23/46、24/46**，仍漏掉近半查询。词典编写时已见过查询词汇，不能视为留出词汇上的语言测试。
- 可执行的细粒度到粗粒度路由，在理想合成向量几何下找回 **46/46**；加入扰动后，最终 128 候选仅为 **31/46、35/46**。直接拼接粗粒度原文达到 26,220 字符，超出适配器每段 8,192 字符限制；要池化精确原文向量，又须先生成全部 4,096 个原文嵌入。

这些实验不作为额外选择器、词典或服务商功能发布。保留失败是为了说明候选路由依赖的假设，不证明路由普遍不可行。全范围扫描消除合格来源被挡在候选池外的漏召回，但代价可能是数分钟处理及更多原文传输。真实嵌入相关性、多跳推理、多语言质量和生成答案正确性仍须单独评估。

- 4,096 片段冷扫描需要 **129 次尝试**：1 次查询与 128 批正文；保留 2,000 条有效缓存后，立即热扫描需要 **67 次尝试**：1 次查询与剩余 2,096 片段的 66 批正文。此处不含重排和失败；热查询并非免费。
- **4 个协议正例、4 个本地通道回归和 4 个封闭语料负例**分别计数，协议案例不并入独立召回分母。迟位精确编号／伏笔保留本地顺序；合成负例不是全文无答案的证据。
- 中间批次收到 HTTP 500 后暂停，明确重试以 **130 次尝试**完成，不重复计算已接受的覆盖。缩小至 2,000 片段后，保留普通语义融合并排除缓存中的未来来源。
- 会话测试使用同一向量对照流式与完整物化 Top-K；客户端／界面测试覆盖零请求计划、小范围预算、无效／重复／过期授权、缓存优先淘汰、损坏批次、时间边界、取消、到期、Worker／回调丢失、纯本地结束与来源新鲜度拒绝。

这是预设向量的工程和协议结果，**不是 46/46 的真实嵌入准确率**；未新增或评估外部模型／嵌入服务。全范围评分本身不能把依据分类为有支持、依据不足或不确定。

### 生产适配器容量测量

2026-10-22 的运行测量本地已提交实现 `86eb1a2760bba172b9ab33adb262d3fd3f7bb36b`，受跟踪生产输入干净，各次运行前后生产／脚本哈希保持不变。每个维度使用一个独立新 Node 进程，连续执行三对冷／立即热缓存扫描。此处“冷”指已建好本地索引上的空向量缓存，并非冷建本地索引；另有 `syncMs` 记录初次索引耗时。环境为 Node v24.19.0、Linux x64、AMD EPYC 9V74、九个可见逻辑 CPU，启用显式 GC。本容量样本使用固定三前提查询 `eval-multi-9`，不是另一轮 46 查询的质量评估。

| 128 | 472.239（454.257–491.732） | 329.134（325.391–329.662） |

| 维度 | 冷缓存 CPU 中位数，ms | 立即热缓存 CPU 中位数，ms | 进程 RSS 高水位，MiB |

| 128 | 238.022 | 152.556 | 296.816 |
| 512 | 636.912 | 341.397 | 312.762 |

CPU 为进程用户态与系统态之和，不是墙钟时间。18 次扫描全部完成，冷／热分别为 129／67 次尝试，冷热最终结果相同，共通过 **144 次精确来源检查**。每次冷扫描发送 411,809 个原文 UTF-16 单位，热扫描发送 210,207 个，不含查询文本；热扫描先为 2,000 条保留缓存评分，仍需嵌入 2,096 个片段。未请求外部网络或真实模型。

在 4,096 维下，常驻缓存向量占 **31.25 MiB**，但采样 ArrayBuffer 峰值为 **52.901 MiB**，采样堆峰值为 **195.937 MiB**，进程 RSS 高水位为 **431.141 MiB**，因此缓存上限不能代表总内存。串行请求的稠密 JSON 响应合计为冷 **163,212,223 字节**／热 **83,538,213 字节**，最大单个响应 **1,274,789 字节**。该总量是进程内构造的累计响应量，不是同时保留量，也不是真实网络流量。

[汇总记录](testing/memory-full-scan-2026-10-22/summary.json)对应 [128 维](testing/memory-full-scan-2026-10-22/dense-128.json)、[512 维](testing/memory-full-scan-2026-10-22/dense-512.json)及 [4,096 维](testing/memory-full-scan-2026-10-22/dense-4096.json)原始记录，保留环境、语料／实现／脚本身份、逐次耗时／CPU／内存、来源检查、请求／响应大小和结果摘要。每种状态三个样本只能描述本次运行，不代表统计置信度、两个实现的成对加速或生产延迟保证。

[`benchmark-memory-full-scan.mjs`](../scripts/benchmark-memory-full-scan.mjs) 使用稠密小数合成响应，执行生产适配器 JSON／`number[][]` 解码及 Float32 转换。测量包含合成响应构造，不包含浏览器 Worker 传输、IndexedDB 正文加载、编辑器工作或真实网络／模型等待。来源校验读取固定内存快照，不测量已提交存储加载。实际 Writer／Lab 每批新鲜度重读可能显著增加耗时；全库正文加载和来源序列化仍是单独的限制。进程高水位包含语料构造和本地索引；10 ms 采样可能漏掉更短的分配峰值。这是特定主机上的 Node 容量观察，不是浏览器内存、SLA 或真实嵌入质量。

仅说明规模的**算术投影**：按每次串行请求固定 100 ms，129／67 次分别为冷 **12.9 秒**／热 **6.7 秒**；按 1,500 ms，则分别为 **193.5 秒／100.5 秒**，尚未加本地计算、来源校验、重试或重排。它们不是实测服务延迟，也不保证完成时间。默认 65 秒额度可能合理地触发暂停，延长必须明确授权。

## 复现与验收

安装依赖后，从仓库运行。此工程门槛只使用合成适配器：

```bash
node --import tsx scripts/smoke-memory-full-scan-session.ts
node --import tsx scripts/smoke-memory-full-scan-client.ts
node --import tsx scripts/smoke-writer-full-scan-ui.ts
node --import tsx scripts/smoke-memory-full-scan.mjs

# 生产实现冻结后，依次在独立新进程中运行。
for dimensions in 128 512 4096; do
  node --expose-gc --import tsx scripts/benchmark-memory-full-scan.mjs \
    --dimensions=$dimensions --rounds=3 --label=dense-$dimensions \
    --output=artifacts/memory-full-scan
done

npm run typecheck
npm run lint
npm run smoke:all
npm run build
npm run test:browser-memory-full-scan
```
