# 事实关系图与原文依据

[English](memory-fact-graph.md) | [简体中文](memory-fact-graph.zh-CN.md)

从侧栏 **记忆检索 · 原型**（`#/memory`）进入事实关系图区。这是第三阶段的功能：把人物、事件、物件、地点之间的关系关联到支持它的精确章节原文；不包含内嵌 Agent，也不代表第二阶段章级持久化已经完成。

## 使用图谱

1. 选择独立示例或实际小说，并设置最后允许披露的章节。实际小说使用已提交正文；请先在 Writer 保存，再返回记忆检索页面。
2. 点击**添加关系**，选择已披露章节，复制精确原文到表单，点击**加入依据**，再填写两端的实体类型与原文名称，以及关系名称。新手工关系按原文明示记录，请仅填写原文直接支持的关系。同一关系可以关联多段原文，也可以从当前检索依据打开已填好锚点的表单。
3. 点击 Cytoscape.js 画布中的边，或对应关系列表项。依据面板显示每条支持原文的章节、当前修订号、UTF-16 范围和精确片段。
4. 审阅、编辑、删除或确认关系。作者确认是独立的审阅状态，不会覆盖原来的依据类型和模型／作者来源。编辑关系会清除确认状态，保留原依据类型与来源。
5. 按名称、关系或原文词句搜索符合范围的图谱，回看远距离关联与伏笔。搜索先于展示上限执行，初始画布未显示的关系仍可通过搜索找回。

画布和关系列表使用同一批过滤后的关系，节点由这些关系生成，不读取全书所有身份的全局目录。名称必须在关联原文中按字面出现。节点身份由实体类型与精确名称共同决定；原型不会自动消歧同名人物、合并别名或推断身份变化。

## 标记的含义

| 标记 | 含义 |
| --- | --- |
| 原文明示 | 该关系被标记为原文直接陈述。这是分类，不是应用自动证明的结论。模型创建的“明示”关系仍明确标注为模型提议、未经确认。 |
| 推断 | 该关系是模型对所引原文的解释。编辑或确认不会改变其原有推断类型和模型来源。 |
| 作者确认 | 作者显式审阅并确认了关系，原有明示／推断类型和模型／作者来源仍保留。确认不能让过期或未来原文变为合格依据。 |

精确引文校验能够确认支持文字来自哪里，但不能证明关系、实体类型或推断本身正确。作者仍需审阅关系名称，避免把后文秘密提前填入绑定前文章节的注释。模型同样可能理解错误；应用不会把模型标记的“明示”视为独立验证。

## 修订与披露约定

每条原文锚点记录作品、稳定章节身份、标题与纯文本正文的 SHA-256 修订号、UTF-16 起止位置，以及精确引文。章节在当前列表中的位置决定披露顺序。

只有**全部**依据锚点都匹配当前已提交作品与章节修订、精确原文范围，且都在截止章节内，关系才符合展示条件。多前提推断不能因为第一条依据出现在前文，就提前展示整体结论。章节重排立即改变披露范围；删除章节会使其关联关系退出可见图谱。

修改来源章节的标题或正文，会使该章关联的全部关系失效，包括作者确认过的关系。原型保留已存注释，但隐藏整条关系；不会把旧引文搬到新修订，不会只保留推断的一部分前提，也不会悄悄重新抽取。审阅改稿后，应从当前原文创建新关系。修订号取内容哈希，因此恢复完全相同的标题和正文后，已有锚点可能重新有效。依据面板用于查看当前有效来源，不是历史章节版本浏览器。

切换作品、来源或截止章节时，会清空过期可见选项与待审提议。模型请求前，只有所选、校验通过且已披露的片段才符合发送条件。迟到响应不能恢复已被替换来源或披露范围中的事实。未来关系、其节点名称和存储数量不会通过可见图谱泄露。

这些检查适用于事实关系图和其抽取请求。既有 Writer 生成提示词、`writing_search`、人物设定和全书摘要不会自动继承这套约定。

## 可选模型提议

模型抽取由用户显式触发，使用当前生成 API 配置，包括输出／思考预算；它与记忆检索页的嵌入／重排设置相互独立。手工创建图谱不需要模型或 API 密钥。

请求只包含已选原文和返回关系的指令，不包含整章、章节标题、作品元数据、已有图谱、MCP 结果、Skills 或 Agent 上下文。每次抽取最多八段原文、总计 8,000 个已选 UTF-16 字符，以及 16 条关系提议；单段最多 2,000 个 UTF-16 字符。请求超时为 60 秒，支持取消。

应用校验响应结构、实体类型、来源引用和两端名称的原文依据。实际作品／章节／修订／范围由应用绑定，模型不能替换来源身份。格式无效的响应会被拒绝。所有提议最初均未确认，必须显式保存才会成为持久化图谱注释；单独执行抽取不会保存或确认关系。

这是针对已选依据的有限抽取，不是无人值守的全书建图。它可能漏掉关系或分类错误。自动化测试使用确定性模型响应，验证请求与校验边界，不代表真实模型的抽取效果。

## 持久化与容量

关系按作品保存在独立 IndexedDB 记录中，不改写小说正文。保存会在同一事务中比较上次读取的图谱版本，再执行更新；并发修改明确报错，不覆盖更新的图谱。存储失败或已存数据格式错误均会提示，不会在加载无效记录时静默替换为空图谱。

图谱注释**不进入系统备份或小说导出**。它仅保存在当前浏览器，清除对应 IndexedDB 记录或站点数据会丢失图谱。重置独立示例会保留已有图谱注释，不覆盖或重新预置已保存过的图谱。本版本还没有图谱导入／导出或过期注释清理界面。过期关系继续保留存储，但从全部活动图谱结果中排除，不会自动删除。

| 边界 | 上限或行为 |
| --- | --- |
| 已存关系 | 每部作品最多 10,000 条 |
| 每条关系的依据 | 最多八个锚点，每个最多 2,000 个 UTF-16 字符 |
| 已存引文／文档 | 每部作品最多 800 万个引文 UTF-16 字符，序列化后最多 2,400 万个 UTF-16 字符 |
| 可见关系 | 来源、截止章节和搜索过滤后最多展示 200 条 |
| 图谱搜索 | 先搜索整个符合范围且有容量上限的图谱，再应用展示上限 |
| 模型抽取 | 每次最多八段／8,000 个已选 UTF-16 字符／16 条提议 |
| 实体身份 | 类型加精确原文名称，不跨别名合并身份 |

展示上限用于约束画布开销，不代表可同时渲染任意规模的全书图谱。[超长篇测试](memory-stress-tests.zh-CN.md)中已有的检索压力数据衡量的是检索子系统，不是图谱抽取或布局吞吐量。

## 验收检查

- **修改旧章**：创建并确认关系，再修改其来源章的任意内容并保存。返回图谱刷新来源后，旧关系、仅由它引入的节点和依据必须消失；新关系必须绑定新修订。
- **找回伏笔**：为前文物件或事件建立有引文支持的关系，再在较晚截止章节下按名称或关系搜索。结果必须保留早期章节与精确片段。这是有来源的注释回查，不是自动证明某段原文构成伏笔。
- **避免未来泄漏**：保存后文身份关系，以及同时依赖前文和后文的推断。截止后文章节之前，两条关系及其独有的未来节点名称都不能出现；将截止章节调回前文，还必须清空选中的未来关系并拒绝迟到模型提议。
