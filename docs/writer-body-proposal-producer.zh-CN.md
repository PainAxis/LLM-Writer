# 单窗口正文提案生产器：离线就绪验证

[English](writer-body-proposal-producer.md) | [简体中文](writer-body-proposal-producer.zh-CN.md)

状态：实现正在验证。没有授权真实外部模型、凭据使用、付费试运行、自主提取或全书语义验收。原生 IndexedDB／实际 UI 验收只在单独获准的 CI 中运行；未执行的检查保持 NOT RUN。

## 新增的实际路径

Campaign Lab 可以从当前已接纳正文的任意合法窗口准备提案，不再只能加载固定示例。每一步都由作者明确触发：接管已完成的源 Campaign → 可选的本地正文修订 → 选择窗口及规划引用 → 准备精确输入 → 调用一次已注册的离线控制适配器 → 持久保留结果 → 将可支持的提案及未解决观察一起编译为只读审阅。

默认应用没有获准的传输适配器。它可以展示并准备未配置的 SDK 描述，但“调用”保持禁用，执行引擎也会独立拒绝。工程测试注册真正的受限 SDK 适配器，连接本地合成端点。这证明传输、来源和持久性边界，不证明真实模型的提取质量。

最初只支持既有经过完整验证的 3 章／60 章规划图；通用性指其中任意已接纳正文，不是任意无类型 Campaign 或普通 Writer 小说。生产器不会修改 Writer 正文、规划 canon 或事实图，不会自动选择下个窗口、检索、重试、修复，也不会把提案升级为既定事实。

## 明确的来源与持久化版本

生产器使用既有 Campaign head 键上的 **Campaign v3**。显式接管先完整核验已完成的 v2；仍有开放写作请求／预留时拒绝接管。所有不可变 v2 字节、哈希、计数规则和累计预算保留原样。新 head 让已加载的 v2 写入在 CAS 时失败，旧读者不能忽略隐藏的生产器旁账。v3 checkpoint／receipt 使用独立版本键，保持 v2 历史“后继不存在”的检查。未知／损坏版本只拒绝，不重写。

本地正文修订是独立作者动作，不是生产器的自动步骤。它生成新的候选／正文修订，保留父链，并使依赖的后续正文失效；每次重新接纳都需要明确动作和当前依赖。修订提交绑定预览时的精确 head；另一标签页若在期间改动，必须重新预览，不能静默覆盖。人工修订明确不属于自主创作，不能计入最终自主小说验收。

生产器 request／response／review 使用 v3 总账下的闭合 v1 契约。**生产器 Body Evidence packet 使用 v2**，保留真实注册适配器来源及未解决清单计数／摘要，复用既有引用、前提闭包和来源编译核心。手工 Body Evidence v1 契约及规范字节输出不变。

## 一次调用，包括未知结果

请求状态为 `reserved → dispatch_intent → response_retained → resolved`；intent 与 retain 之间允许 `outcome_unknown`。

- 准备只进行新鲜核验读取，不写入、不调用模型。
- 调用前冻结精确输入、来源根、原始偏移、规划闭包、适配器／配置身份和有限上限。
- SDK 最后一次请求前检查持久提交 intent。只有刚刚赢得该提交的调用获得一次性运行时许可；保存的 JSON 和重放 receipt 都不授予调用权。
- 重复点击共享同一操作；相同操作 ID 配不同内容属于冲突。
- intent 后崩溃，即使尚未发出 HTTP，也保持未知／已占用。超时、取消、缺少用量或响应都不是零费用。
- 完整有界响应先持久保存再解析。无效 JSON 是已保留的拒绝结果，不是成功的空清单。
- 重载／恢复只在本地显式执行。已保留响应可无传输重新编译；未知调用不得自动重发。
- 最终展示前重新核验当前来源、配置和所有权，并通过共同 raw-head CAS 提交。迟到或过期结果不能恢复已取消的权限。

activeMs 表示已接纳请求／已提交元数据的保守预留，不是所有失败读取或只读准备的实际累计 CPU 时间。恢复编译前先检查剩余额度；每次本地动作仍有自己的期限，失败写入不能声称已完成持久扣账。恢复元数据操作有明确的有限记账，不能延长已到期的请求所有者，也不能创造另一份消费额度。写入 ACK 不确定时，先核验确切 receipt，之后才能决定是否重试。

## 明确的冷核验会话与截止时间

生产器采用新的可选 **`producer-verification-session-v1` 执行契约**，不是把旧读取改名或宣称它更快。公开 v2 读取及单体 v3 读取保留原有 API 和三秒操作语义。此前生产器 N60 与保存快照的单体三秒失败仍是失败证据；新契约不能代授该门槛通过，也不声称 CPU 性能提升。

每个 owner 最多开始一次冷核验，且只能选择一个用途：为显式接管验证已完成、已注册、无开放义务的 v2 基线，或验证当前 v3 总账。绝对截止点固定为 `min(owner.started + 10 秒, owner.deadline)`，不会因批次、进度回调、让出执行、最终复核或重试续期。检查、接管、准备、修订、取消和恢复的整个 owner 仍最多十秒；调用仍最多六十秒，其中首次核验只使用最初十秒，不额外增加时间。每次实际原始 IO／CAS 等待仍最多三秒，并受所有外层截止点约束。

按时间顺序重放保留全部 schema、规范字节、哈希、父链、来源、请求状态、精确写入计量及共同预算检查。每次推进最多重放八个操作，即使读取批次包含三十二项；约五十毫秒主动让出真实宿主事件循环，连续同步校验段上限 250 ms。它们是分别测量的要求，已完成 Promise 的微任务不算宿主让出。校验、IO、调度和最终复核都消耗同一固定总时限。进度只含计数和阶段，不会把部分来源或解析状态作为准备、修改或派发权限。

同一个仓库私有证明池覆盖 v2 来源与 v3 尾部，沿用 64 MiB／8,193 条目／512 个活跃载荷上限。冷会话只能完整捕获或拒绝；接纳／容量失败不能静默漏记录，也不能取得第二份额度。计数验证前只使用绝对上限，完整重放后还要求保留的序列化 key／value 字节不超过已验证总账 W。这是序列化保留上限，不是 JavaScript 堆上限。

返回成功前重新读取重放使用的每个不可变原始记录，核对完整预期键／数量、字面字节、目录前缀、后继边界及实际 head。批次与暂停之间也检查 head；来源变化只拒绝，不重定基准。这不是对全部历史键的事务锁，最终修改仍以实际 head 和仅新建写入目标的 CAS 保护。公开快照与私有验证状态分离。

成功只销毁推进能力，原有同一份精确复核证明可在同一 owner 的后续动作使用。后续动作仍受三秒仓库操作上限限制，重新检查来源并完整重放 v3 尾部。owner 完成、取消、导航、替换、到期或出错即销毁证明。证明丢失后，同一 owner 不能重新捕获或再开冷会话；旧冷路径回退仍最多三秒，允许拒绝。既有独立有界元数据恢复不授予模型调用权。不保存核验进度；重载只从原始记录显式重验，不信任保存的游标。

接管只通过一次精确 head CAS 消耗私有 v2 基线，不重复冷重放、不在同一 owner 内核对不确定 ACK。CAS 失败或确认不确定即结束本次 owner。新的显式重试可以验证已存在的 v3 总账，只识别完全匹配的接管 receipt；不能回滚、重新接管或在旧 owner 内改换用途。接管之后，已加载 v2 写者仍在精确 head CAS 处失败。

协作检查、最终 CAS 和结果展示共同使用同一绝对截止点，定时器迟到不能绕过它。已经持久成功但确认迟到的写入按精确 receipt 核对，不当作未写入。供应商未知结果仍保持已占用／未知；核验不重发 HTTP、不退还预留。若完整核验及所属元数据动作无法在固定十秒 owner 时限内完成，就停止验收，不提高或重置上限。调用总计仍有六十秒，只有首次冷阶段限于最初十秒。核验完成事件不等于动作成功：完成监听器可以同步取消所有权，此时随后发出取消事件，但不返回快照或派发权限。

## 上限与共同记账

总约束保持 **W + U + P ≤ 67,108,864 字节**。W 是累计成功 key＋value 写入；U 是未结清的未来写入预留；P 是受保护的恢复容量。接管、生产器记录、本地正文修订及每次 head 覆盖都使用同一总账，不新增第二份 64 MiB 配额或调用额度。

| 边界 | 初始上限 |
| --- | --- |
| 生产器请求 | 每个接管 Campaign 最多 8 个，同时受原有剩余累计额度约束 |
| 可派发活动请求 | 1 个 |
| 正文窗口 | 单章一个窗口，4,096 个原始 UTF-16 单元，必须位于标量边界 |
| 完整选中规划闭包 | 32 条记录／12 KiB |
| 精确序列化输入 | 32 KiB UTF-8／16,384 UTF-16 单元 |
| 输出 | 8 项、16 个引用范围、32 个主体提及 |
| 返回文本／解码 HTTP 响应 | 16 KiB／64 KiB |
| SDK 请求 | 1 次、1,200 个配置输出 token、禁用 reasoning、30 秒 |
| 生产器动作／准备句柄 | 60 秒／5 分钟 |
| 实际 IO／CAS、后续仓库操作 | 3 秒，同时受 owner 截止点限制 |
| 冷会话／元数据 owner／原有预览 | 同一固定 10 秒内／10 秒／10 秒 |
| 核验推进／连续同步段 | 8 个重放操作／250 ms；约 50 ms 让出真实宿主任务 |
| 证据 packet／完整 review | 64 KiB／96 KiB |

生产器五阶段写入使用单独证明的包络，而不是冒充写作 artifact。origin／response／review 的最终 key＋value 大小分别检查；固定宽度计量和最终重新计数先于 CAS。完整可识别终态只释放未用未来写入空间，不退还累计请求资源。未知结果的开放分配在取消、替换、重载和到期后保留。

已经使用 123 次尝试的 N60 来源不会获得 8 次新额度；剩余尝试、活动时间、操作和存储上限可能只允许更少调用。容量拒绝不能算作覆盖成功。

## 披露与未解决清单

提示只包含选中的精确正文窗口和作者选择、引用闭包完整的规划记录，准备界面展示实际输入。不会自动加入全部规划、标题、其他正文、事实图、检索结果、工具或聊天历史。规划可能含作者专属／未来意图，不等于当前正文事实、角色知识或读者披露许可。

首批支持独立世界断言、归因信念和叙述者提案。角色变化、伏笔／回收关系，以及缺少外部前提的观察保持未解决。返回的未映射主体／主题、含糊归因／引用和容量缺口必须带精确原始引用可见；不会凭空补规划记录让它们通过。

闭合解析拒绝重复／额外字段、无效引用、拆分代理项、错引文本、超大输出和不支持结构。不会搜索后搬移重复引文、规范化原文、修复 JSON，或丢弃坏项后宣布子集成功。

请求／提供的文本、已完成请求、生产器声明的检查范围和独立语义审阅分别记账。空输出只表示返回了空提案，不证明没有事实或漂移；饱和输出明确增加整个所选窗口的容量缺口。正确引文上的错误含义仍未经语义审阅。即使移除外层 review，v2 packet 也保留未解决计数、饱和状态及清单摘要，不能伪装成完整审阅。

## 保留与尚未开放的真实调用

请求、有界原始响应和 review 仅在本地 Campaign 生命周期内保留，受同一容量／请求数限制。没有自动逐出、含来源导出或普通 Writer 备份集成。执行到期不等于擦除、预算退款或未知调用结清；清除浏览器数据会丢失证据，使以后核验变为未知。

这是**按容量有界的离线保留**，不是按时间删除，也不代表真实模型就绪。真实使用还需批准端点／模型及披露／凭据授权、可执行的输入 token／reasoning／金额上限、中英文质量校准，以及明确的有限保留／删除契约。估算 token 字符比例或假设价格都不能授予执行权。

## 验证和最终目标

专项检查覆盖解析／编译兼容性、真实 SDK 本地端点、v3 迁移／记账／故障恢复、执行链路和 UI 所有权。串行 N60、仅 CI 的原生／实际 UI 控制使用冻结身份及上述明确执行契约。`body-producer-readiness-report-v2` 分别报告 owner／会话耗时、实际 IO／CAS、后续操作、连续同步段、宿主让出、最终复核覆盖与保留证明字节。仓库操作／冷读取整体耗时仍可见；旧单体三秒生产器门槛明确不授予通过，既有 v2 截止时间门槛仍必须通过。owner 终态计数互斥：完成、拒绝、取消或到期。`ownersExpired` 记录引擎 owner 或它已接纳等待可见的到期；内部 CAS 超时若封装为 `storage_unknown`，可能计入拒绝。因此到期 owner 为零不能代替独立原始 IO／CAS 截止检查，更不能证明写入没有发生。浏览器分别记录实际 ProducerLabPanel 生命周期矩阵与小型真实 App／路由／CampaignLab 集成流程，真实 App 流程另行覆盖核验中进度、取消和冷重载，不混入面板分母。两者使用生产引擎、原生 IndexedDB 和 SDK；只有受控 CI 构建显式注入本地适配器，普通应用启动不提供适配器，仍未配置调用权限。这些原生门槛未在本地执行，也不由 Node 测试代授通过。公开证据仅允许闭合的无来源哈希／计数／状态；不上传正文窗口、请求、原始回复、packet、数据库转储或含来源 trace。

最终要求仍是中英文各一部百万正文 Unicode 标量字符的自主小说，并对整部作品的题材、剧情、人物／知识及伏笔进行独立验收。两个完整 Campaign 及其语义审计保持 **NOT RUN**。详见[最终验收契约](writer-agent-longform-acceptance.zh-CN.md)。
