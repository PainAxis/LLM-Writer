# 超长篇记忆压力测试

[English](memory-stress-tests.md) | [简体中文](memory-stress-tests.zh-CN.md)

这些测试扩展了[记忆原型](memory-prototype.zh-CN.md)的小规模示例验收，分别检验本地容量、检索正确性、服务故障处理、浏览器工作流程和真实模型召回。某一组通过，不代表其他能力也已经通过。

## 工作负载与结果含义

| 分组 | 工作负载 | 能验证什么 |
| --- | --- | --- |
| 本地引擎 | 百万至千万字符的确定性多卷中文故事，包含反复出现的人名、地点、相似伏笔和预埋事实 | 索引容量、实测检索耗时、原文依据、版本失效与披露边界 |
| 混合检索／服务 | 百万字符语料与本地 HTTP 服务，返回受控的 512 维向量及重排结果 | 生产适配器请求、缓存行为、候选范围、失败回退和取消；不验证模型智能 |
| 浏览器 | 按应用的章节 blob 持久化格式存储长篇小说，再通过实际构建产物检索和改稿 | Worker 集成、连续检索、已保存正文读取、多标签页改稿及可见依据 |
| 真实 Jina | 完整的公版中文小说与运行前确定的问题 | 对这些文本、问题、模型及账户的实际召回效果，包括漏召回；不代表通用小说创作质量 |

程序化语料变化人物、地点、日期、数量、行动、对话及段落结构，用预埋标识符明确预期来源，并设置别名相似、来源距离较远的伏笔。它比重复填充段落更丰富，但仍属于生成测试数据。精确标识符命中率和人工伏笔召回不能当作自然语言语义召回率。

体量统一采用 JavaScript UTF-16 码元数，与引擎的原文偏移和容量检查一致，不等于中文词数、token、文件字节数或不同文学词汇数。程序化语料含补充平面的 Unicode 字符，用于检查原文范围。浏览器语料实际存储 1,560,000 个原始字符，正常的 Writer 纯文本转换会去掉一个末尾换行，实际索引为 1,559,999 字符；断言独立逐章转换，分别核对存储与索引数量。

## 压测发现并修复的问题

扩大工作负载后发现了小规模验收未暴露的两个问题：

| 问题 | 修复前 | 修复后 |
| --- | --- | --- |
| 大量部分匹配的伏笔挤掉融合列表中的精确正文命中 | 24 个复合事实查询中，预期原文进入 Top-8 的为 **0/24** | 平衡本地通道权重后为 **24/24**，均位于第 2 名；另外 24 个伏笔查询仍全部位于第 1 名 |
| 来源未变时，每次同步仍重建关键词索引 | 对 1,296,626 字符公版语料的三次重复同步为 **9,529.63／9,576.07／10,677.62 毫秒** | 完全相同来源复用后为 **2.69／1.51／1.15 毫秒**；首次构建仍约 **9,881 毫秒** |

[排序对照](testing/memory-stress-2026-10-04/ranking-before.json)与[修复后结果](testing/memory-stress-2026-10-04/ranking-after.json)使用同一份冻结的 v1 语料：600 章、1,320,000 字符、1,200 个正文片段和 300 个伏笔。最终容量测试改用了覆盖更多模板／地点的随机生成器，不能直接将其耗时或质量与该 v1 排序实验混比。排序修复也不代表首位结果完全准确：本次 24 个事实来源仍全部位于第 2 名。

[同步对照](testing/memory-stress-2026-10-04/sync-before.json)与[复用结果](testing/memory-stress-2026-10-04/sync-after.json)测量的是对 1,178 个公版正文片段执行 `structuredClone` 及生产同步调用，不含浏览器存储、Worker 通信、渲染、检索或服务调用。复用省去了不必要的分词，不会加快首次构建或来源改变后的重建；三次重复测量也不是分位数基准。

## 压测记录——2026-10-04

### 本地容量与改稿

[本地报告](testing/memory-stress-2026-10-04/local.json)通过 **36 项工作流程检查、777 次检索及 5,151 条原文依据检查**，外部请求为 0。各体量均在独立 Node 进程运行。v2 程序化语料实际使用了全部 72 个人名、36 个地点和 8 种段落模板；字符串不重复不代表文学内容丰富度。

| 字符／章节 | 正文片段／伏笔 | 首次构建 | 修改 30 章后重建 | 未变来源同步 | 重复检索 p50／p95 | 进程峰值 RSS |
| --- | --- | --- | --- | --- | --- | --- |
| 1,320,000／600 | 1,200／300 | 7.73 秒 | 7.32 秒 | 1.92 毫秒 | 6.09／10.44 毫秒 | 621.63 MiB |
| 3,300,000／1,500 | 3,000／750 | 18.92 秒 | 19.20 秒 | 3.16 毫秒 | 16.35／54.03 毫秒 | 1,311.51 MiB |
| 10,500,000／2,500 | 10,000／1,250 | 60.69 秒 | 59.42 秒 | 6.76 毫秒 | 42.34／145.42 毫秒 | 2,005.57 MiB |

重复检索分位数各来自 48 次仅测引擎的查询。三组的 48 个预埋标识符／伏笔查询均在 Top-5 找到预期原文。另列的 12 个自然多实体问题，Top-5 分别为 **11/12、10/12、8/12**，Top-8 分别为 **12/12、11/12、11/12**。工作流程断言通过不能写成自然查询召回率 100%。

测试还检查了修改 30 个旧章后排除旧事实／伏笔、12 个末期身份按章节边界隐藏及揭示、章节重排、删除 20 章，以及复用章节 ID 的作品切换。20,000,001 字符来源在索引前被拒绝，这不代表已经验证了 2,000 万字符上限处的正常运行。

本地运行环境为 Linux x64、Node 24.19.0、Intel Xeon Platinum 8573C，可见 9 个逻辑 CPU、总内存 9.734 GiB，每组 Node 堆上限 2,240 MiB；共享环境中同时还有其他测试工作。千万字符结果也暴露了实际成本：**改稿后仍需约一分钟重建，进程峰值 RSS 约 2 GiB**。能够跑完，不代表适合所有桌面或移动浏览器。

### 受控 HTTP 混合检索

[混合检索报告](testing/memory-stress-2026-10-04/hybrid.json)的 11 组验收全部通过，共执行 112 次同步／检索动作。主体来源为 **600 章、1,320,000 字符、1,200 个片段**，使用 512 维合成向量。**80 次热查询**均找到预期事实／伏笔来源，其中包括 20 次远距离伏笔查询。这验证的是确定性服务下的工程正确性。

| 测量项 | 观察结果 |
| --- | --- |
| 冷启动完整动作，含来源同步及嵌入 | 9,462.77 毫秒；40 次 HTTP 请求；每次请求额外加入 25 毫秒模拟延迟 |
| 80 次热查询完整动作，含新副本／同步 | p50 **19.08 毫秒**、p95 **25.27 毫秒**；本机 HTTP，不加模拟延迟 |
| 单独的热同步 | p50 2.29 毫秒、p95 3.02 毫秒 |
| 单独的热检索／服务工作 | p50 16.71 毫秒、p95 22.45 毫秒 |
| 修改 20 个旧章 | 重新嵌入 40 个片段，复用 1,160 个，排除 20 个陈旧伏笔 |
| 第 19 批正文请求失败后重试 | 保留 576 个有效向量，只补交缺失的 604 个片段 |
| 整次运行的 HTTP 流量 | 362 次请求；请求 28,733,177 字节、响应 23,602,163 字节；原文外发范围违规 0 次 |

429／500、向量维度错误、截断 JSON、非法重排索引及请求中的取消，均执行了回退或取消，并验证后续恢复。2,420,000 字符／2,200 片段的来源明确报告语义回退，**嵌入请求为 0**，仍可重排本地候选。这是容量边界结果，不能算全量混合检索成功。总预算分支将生产的 65 秒预算明确加速为 **350 毫秒**，用于检查控制流程，不是真实等待 65 秒的延迟观察。

进程观察峰值 RSS 为 1,417.63 MiB，当时同时保留多个测试索引；冷启动动作结束时 RSS 为 399.60 MiB。两者都不等于单部小说的独立内存分配。本地哈希向量、词面重排及本机通信耗时不能预测真实 Jina 的质量或延迟。

### 完整公版合集的真实 Jina 测试

[已完成的 Jina 报告](testing/memory-stress-2026-10-04/jina.json)针对 **1,296,626 字符、171 章、1,178 个片段**执行了全部 22 个预先固定的问题，使用 512 维 `jina-embeddings-v3` 及 `jina-reranker-v2-base-multilingual`。18 个远程正向问题均实际使用语义检索与重排，没有把回退查询计为混合检索成功。

| 18 个正向问题的预期来源召回 | 纯本地 | Jina 混合检索＋重排 |
| --- | --- | --- |
| Top-1 | 3/18（16.67%） | 7/18（38.89%） |
| Top-5 | 5/18（27.78%） | 15/18（83.33%） |
| Top-8 | 6/18（33.33%） | 16/18（88.89%） |

这组固定的小样本达到了预先设定的 Top-5 80% 目标。漏召回仍保留：鲁智深在菜园展示力气的问题，其预期原文排第六；红孩儿受封身份和凤仙郡干旱原因两个问题的预期片段未进入 Top-8。这测量的是预先指定原文的召回，不是生成回答或通用文学理解。

两个未来披露检查通过；替换旧章事实后，旧事实被排除，新事实以新修订号召回，原文外发范围违规为 0。但 **两个不可回答问题在本地和远程模式下都各自返回了八条片段**。当前检索器不能可靠识别所问事件没有原文依据；后续回答生成不能把“有检索结果”当作“答案有依据”。

**首次冷启动未能在生产预算内完成混合检索。** 前三次各运行约 65 秒后回退，第四次再用 26.19 秒才完成 1,178 片段的缓存及检索，四次准备共 221.19 秒。这说明断点续建有效，不能写成单次冷启动成功。18 个正向热查询的完整动作耗时为 p50 **10.07 秒**、p95 **17.54 秒**。

真实服务整次运行耗时 531.72 秒，共 92 次请求、提交 2,857,567 个 UTF-16 码元。服务报告总 token 数 3,508,329，这是报告用量，不是已计算的金额。请求通过临时 curl 桥接访问运行环境代理，耗时包含该传输层，真实浏览器 CORS 仍未验证。报告记录了受测引擎版本及后续陈旧伏笔复用调整；这份语料没有伏笔标注，因此该调整不改变其受测来源路径。

## 运行方法

```bash
npm ci
npm run test:memory-stress-local
npm run test:memory-stress-hybrid
npm run build
npx playwright install chromium
npm run test:browser-memory-stress
```

`ci-memory-stress` 任务运行本地容量与受控服务测试，另一个 `ci-memory-browser-stress` 任务并行运行真实构建产物的 Chromium 压力场景。已有冒烟与较短的浏览器回归保持独立，压力脚本不计为新增冒烟组数。

可选的付费服务测试：

```bash
npm run test:memory-corpus-fetch
# 在进程环境中设置 JINA_API_KEY，不要将它提交到仓库。
npm run test:memory-stress-live
```

真实服务运行器最多发送 180 次请求、4,000,000 个 UTF-16 码元，最多尝试八次填充正文向量缓存。每次尝试均保留生产实现的 65 秒远程预算。报告分别记录首次冷启动是否完成、后续尝试是否完成，以及各查询是否实际使用语义检索；不能把多次准备合计完成描述为单次冷启动成功。

本地与服务报告位于 `artifacts/memory-stress/`，浏览器报告及截图位于 `artifacts/browser-memory-stress/`，真实服务报告为 `artifacts/memory-stress/jina.json`。断言失败后仍保留可用诊断产物。对应运行完成后，经检查且不含密钥的记录保存在 `docs/testing/memory-stress-2026-10-04/`。

## 验收规则

- **修改旧章：**改稿后，检索及依据必须对应当前标题／正文哈希与精确原文范围；绑定旧修订号的伏笔应失效。旧查询仍可能命中新正文中的共同词，这本身不代表旧事实残留。
- **远距离伏笔：**要求命中预期来源章与原文，不能只判断结果非空。人工设置的伏笔别名与未标记的语义查询分别统计。
- **披露边界：**同时检查展示依据和发往服务的请求内容是否符合截止章节。大量高相关未来片段不能挤掉当前可用来源；章节重排后按新顺序确定披露范围。
- **故障及竞争：**服务返回无效数据、预算耗尽、取消和过期异步请求，均不能恢复旧作品、旧章节版本或旧披露范围。明确回退到本地与混合检索成功分别记录。
- **持久化：**通过 Writer 改稿，等待保存提交，再由记忆原型读取新版本。只修改内存测试对象不能验证应用的实际持久化链路。

检索通过需要同时满足预期来源与当前版本依据。HTTP 返回成功、结果非空或回退后仍有结果，单独都不够。

## 测量口径

报告保留语料规模、操作次数、成功／失败细节、延迟分布、内存观察及运行环境，不包含 API 密钥或私人稿件。真实服务查询及预期来源在运行前确定，漏召回保留在报告及分母中。

引擎检索耗时只测量检索调用。浏览器的一次检索操作还包含读取已保存章节、同步关键词索引、Worker 通信及结果渲染，不能与引擎查询时间直接比较。同步可复用完全未变的已验证快照，来源改变时仍须重建。混合检索压力运行器的每次完整动作也包含重新克隆来源和同步。冷启动嵌入包括建立正文向量；热查询复用符合范围的正文向量，但仍需嵌入查询，并在启用时执行重排。

p50／p95 必须结合报告中的样本数量阅读。一台机器上的单次结果不是性能服务等级承诺。Node 进程 RSS 包含运行时、语料及其他对象，不等于索引单独占用的内存；浏览器堆内存观察的范围又不同，不能直接与 RSS 比较。

## 当前实现的限制

测试检验现有限制，不会悄悄提高限制来获得通过结果：

- 原型每次检索仍重新读取并验证已保存来源，仅在完整已验证来源完全未变时复用关键词索引；结构合法的陈旧伏笔保持排除，格式异常的伏笔不走该复用路径。任何来源变化仍须全量重建，尚未实现章级增量索引或持久化索引快照。
- 语义检索最多接受 **2,000 个符合披露范围的片段**，按每批 **32 个**顺序请求。超过上限会明确回退到本地检索，不会只处理一部分却不告诉用户。
- 单次服务请求 **15 秒**超时，一次检索的全部远程工作共用 **65 秒**预算。较慢的冷启动可能耗尽预算，而热查询可以成功；两者均需记录实际运行的步骤和回退原因。
- 向量缓存上限为 **2,000 条／32 MiB**，路由生命周期结束后丢弃。对于实际小说，窗口重新获得焦点或小说存储失效通知也会销毁 Worker，因此从 Writer 返回可能需要重新冷启动嵌入全部片段；引擎层的部分向量复用不代表该浏览器流程也会保留缓存。这不是可持久保存的后台索引。
- 修订号由章节标题和完整正文共同决定。修改一句话后，该章所有片段的缓存范围都会改变，即使其他片段的文字未变。
- 重排最多接收 **60 个**融合候选，无法找回不在候选集里的相关片段。
- 现有生成工具和提示词尚未接入原型。因此检索测试不能证明长篇生成一致性、自动伏笔识别、摘要质量或事实关系图能力。

## 语料及远程服务边界

真实文本测试采用 Project Gutenberg 的[《水浒传》七十回本](https://www.gutenberg.org/ebooks/23863)及楔子，以及[《西游记》一百回本](https://www.gutenberg.org/ebooks/23962)。规范化后共 171 章正文、**1,296,626 个 UTF-16 码元**，其中 **1,022,915 个汉字**；原始 UTF-8 下载文件共 3,896,072 字节。测试固定原始文件 SHA-256 校验和，验证章节顺序，并记录问题文件校验和，没有添加重复填充文本。

问题文件在付费运行前固定 **22 项：18 个来源召回问题、2 个未来披露检查、2 个不可回答问题**。纯本地与远程检索使用相同问题及截止章节。召回要求预期章节和预先指定的原文同时命中；Top-1／Top-5 针对 18 个正向问题统计，未来排除与不可回答行为单独记录。不可回答问题返回非空片段不等于正确回答，也不计入召回成功。

下载的全文属于测试产物，不是应用内容。将不同作品合编可以增加索引体量，但它并非情节连贯的一部小说，也不能用于验证跨作品的剧情连续性。

远程测试会将符合披露范围的公版原文片段和预先登记的问题发送到所配置服务，需单独运行并消耗账户的付费用量，不属于常规 CI。如果运行环境需要请求桥接访问服务，桥接会增加耗时；这种运行能验证生产请求／响应适配器及模型表现，不能验证浏览器 CORS。除非另有说明，浏览器测试使用本地受控服务。

生产验收仍需代表性的作者稿件、真实查询分布、目标桌面／移动设备及持续改稿工作。这里的测试用于缩小已知工程风险，不表示所有百万字符工作流已经达到生产可用水平。
